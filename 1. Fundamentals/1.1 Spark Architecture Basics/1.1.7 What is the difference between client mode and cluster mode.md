# 1.1.7 What is the difference between client mode and cluster mode?

The core difference is **where the Spark Driver process runs**. In client mode, the Driver runs on the machine that submits the application (the client or edge node). In cluster mode, the Driver runs inside the cluster, managed by the cluster manager.

- **Driver location**: In client mode, the Driver runs outside the cluster, on the submitting machine. In cluster mode, the Driver runs on a cluster node, often inside the ApplicationMaster container.
- **Client dependency**: In client mode, the client machine must stay alive for the whole application because it hosts the Driver. In cluster mode, the client can exit after submission; the cluster manager keeps the Driver running.
- **Resource management**: In client mode, the ApplicationMaster only requests resources; the Driver on the client schedules tasks. In cluster mode, the ApplicationMaster acts as both the Driver and the resource requester.
- **Fault tolerance**: In client mode, if the client machine fails, the application fails because the Driver is lost. In cluster mode, the Driver is on a cluster node, so it benefits from the cluster manager’s supervision and restart policies.
- **Network latency**: Client mode sends scheduling and status traffic over the network between the client and the cluster. Cluster mode keeps Driver-to-executor communication inside the cluster, which is usually faster and more reliable.
- **Use cases**: Client mode is suited for interactive shells, debugging, and development where you need immediate output on your screen. Cluster mode is suited for production jobs that must run independently of the submitting machine.

> [!IMPORTANT]
> The Driver is the single point of coordination. In client mode, it lives on your machine. In cluster mode, it lives inside the cluster. This determines who must stay alive for the application to finish.

> [!WARNING]
> Client mode is not recommended for long-running production jobs because a client machine failure, network interruption, or laptop sleep can kill the Driver and the entire application.

> [!NOTE]
> Local mode is a third option where the Driver and executors run in the same JVM on one machine. It is for learning and testing, not for distributed production use.

### Clear Definitions

- **Driver**: The process that runs the `main()` function, plans jobs, schedules tasks, and collects results.
- **Client mode**: A deployment mode where the Driver runs on the submitting machine, outside the cluster.
- **Cluster mode**: A deployment mode where the Driver runs on a cluster node, managed by the cluster manager.
- **ApplicationMaster**: A cluster-manager process that requests resources and, in cluster mode, also hosts the Driver.
- **Edge node or gateway machine**: A machine outside the cluster from which users submit applications.

### Worked Example: Same Word Count, Two Modes

Command in **client mode**:
```bash
spark-submit --master yarn --deploy-mode client wordcount.py
```
1. You run the command from an edge node.
2. The Driver starts **on the edge node**.
3. The Driver contacts YARN for executors.
4. YARN starts executors on cluster nodes.
5. The edge node must stay connected until `collect()` finishes.
6. If the edge node disconnects, the job fails.

Command in **cluster mode**:
```bash
spark-submit --master yarn --deploy-mode cluster wordcount.py
```
1. You run the command from any machine.
2. YARN starts an ApplicationMaster on a cluster node.
3. The Driver runs **inside the ApplicationMaster**.
4. The Driver requests executors and runs the job.
5. Your original client can exit immediately after submission.
6. The cluster manager keeps the application alive and releases resources at the end.

In short: client mode keeps the Driver on your side for visibility and interactivity. Cluster mode puts the Driver inside the cluster for independence and production reliability.
