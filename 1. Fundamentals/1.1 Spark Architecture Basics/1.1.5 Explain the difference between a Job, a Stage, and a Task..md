# 1.1.5 Explain the difference between a Job, a Stage, and a Task.

A **Job** is the largest unit. It is created when an action such as `collect()` or `count()` is called. One action normally creates one job. A job contains one or more stages.
A **Stage** is a part of a job that can run without a shuffle boundary. Spark splits a job into stages at wide transformations such as `reduceByKey()` or `groupByKey()`. Each stage contains many tasks.
A **Task** is the smallest unit of work. It usually processes one partition of data. Tasks are what executors actually run.
- **Job**: Triggered by an action. Represents the full computation needed to produce that action’s result.
- **Stage**: A section of a job separated by shuffle boundaries. Stages contain tasks that can run in parallel.
- **Task**: One unit of work for one partition. Executors run tasks on CPU cores.
- **Relationship**: One action creates one job. One job contains one or more stages. One stage contains one or more tasks.
- **Shuffle boundary**: A wide transformation ends a stage and starts a new one because data must be redistributed.
> [!IMPORTANT]
> Job is triggered by an action. Stage is a shuffle-separated part of a job. Task is one partition-level unit of work run by an executor.
> [!NOTE]
> If a job has no wide transformation, it can run as a single stage. If it has `reduceByKey`, Spark usually creates at least two stages: one before the shuffle and one after.
> [!WARNING]
> A large number of tasks is not always bad, but very small tasks add scheduling overhead. Very large tasks can reduce parallelism and increase memory pressure.
### Clear Definitions
- **Action**: An operation that triggers computation, such as `collect()` or `count()`.
- **Job**: The computation triggered by one action.
- **Stage**: A part of a job that can run without a shuffle boundary.
- **Task**: The smallest unit of work, usually one partition in one stage.
- **Partition**: A logical chunk of a distributed dataset.
- **Shuffle**: Redistribution of data across executors, usually between stages.
- **Executor**: A worker process that runs tasks.
- **Driver**: The process that plans jobs, stages, and tasks.
### Worked Example: Word Count
Code:
```python
lines = spark.sparkContext.textFile("huge_log.txt")
words = lines.flatMap(lambda line: line.split(" "))
pairs = words.map(lambda word: (word, 1))
counts = pairs.reduceByKey(lambda a, b: a + b)
results = counts.collect()
```
Step by step:
1. The transformations `textFile`, `flatMap`, `map`, and `reduceByKey` are lazy. They build a DAG but do not run anything.
2. `collect()` is an action, so the Driver creates one **Job**.
3. The Driver sees that `reduceByKey` needs a shuffle, so it splits the job into two **Stages**: a map stage before the shuffle and a reduce stage after the shuffle.
4. If the input file has 4 partitions, the map stage has 4 **Tasks**, one per partition.
5. The reduce stage also has tasks based on the number of reduce partitions, for example 4 tasks.
6. Executors run the map-stage tasks in parallel, write shuffle data, then run the reduce-stage tasks.
7. The Driver collects the final counts and returns the result.
In short: the action creates a job, the shuffle splits the job into stages, and each stage runs tasks on partitions.
