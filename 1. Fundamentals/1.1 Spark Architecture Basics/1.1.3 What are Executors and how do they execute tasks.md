# 1.1.3 What are Executors and how do they execute tasks?

Executors are worker processes that run on cluster worker nodes. The Cluster Manager launches them for a Spark application when the Driver requests resources. Executors do the actual data processing: they run tasks, store data in memory or on disk, and report status back to the Driver. They do not plan the whole job; they only execute the tasks they are given.

- **Run tasks**: Each executor runs one or more tasks in parallel using its available CPU cores.
- **Process partitions**: A task usually processes one partition of data. The Driver decides the tasks; the executor runs them.
- **Store data**: Executors cache or persist data when the application asks for it.
- **Write shuffle data**: During operations like `reduceByKey`, executors write intermediate shuffle files and later read them for the next stage.
- **Report to the Driver**: Executors send task status, results, and errors back to the Driver.
- **Belong to one application**: An executor is normally dedicated to one Spark application and is released when the application finishes.

> [!IMPORTANT]
> The Driver plans and schedules tasks. Executors execute those tasks. A task is the smallest unit of work, and it usually corresponds to one data partition.

> [!NOTE]
> Executors run tasks as threads across their CPU cores. For example, an executor with 4 cores can run up to 4 tasks at the same time.

> [!WARNING]
> If an executor fails, the Driver reschedules its unfinished tasks on other available executors. If a task fails, the Driver can retry it according to the configured retry settings.

### Clear Definitions

- **Executor**: A worker process on a cluster node that runs Spark tasks and stores data for one application.
- **Task**: The smallest unit of work in Spark, usually processing one partition of data.
- **Partition**: A logical chunk of a distributed dataset.
- **Core**: A CPU slot inside an executor that can run one task at a time.
- **Shuffle**: The process of redistributing data across executors, often between stages.
- **Driver**: The process that plans jobs, schedules tasks, and collects results.
- **Cluster Manager**: The service that allocates resources and launches executors.

### How Executors Execute Tasks

1. The Driver creates a job and splits it into stages and tasks.
2. The Driver schedules tasks onto available executors.
3. An executor receives a task and runs its code in a thread on one CPU core.
4. The task reads its input partition from storage or from shuffle data.
5. The task applies the transformation logic to that partition.
6. The task writes its output to memory, disk, or shuffle files, depending on the stage.
7. The executor reports task status and any small result back to the Driver.
8. The Driver uses these reports to track progress, retry failures, and continue the job.

### Worked Example: Word Count

1. The Driver requests 4 executors, each with 2 cores.
2. The Cluster Manager launches the executors on worker nodes.
3. The Driver schedules map-stage tasks for `flatMap` and `map`.
4. Each executor runs tasks in parallel. A task reads one partition of `huge_log.txt`, splits lines into words, and emits `(word, 1)` pairs.
5. Executors write shuffle data for `reduceByKey`.
6. The Driver schedules reduce-stage tasks. Executors read the shuffle data, aggregate counts per word, and write the results.
7. When `collect()` is called, executors send their final results back to the Driver.
8. The Driver returns the collected word counts to your program, and the Cluster Manager releases the executors when the application ends.

In short: executors are the workers that run tasks and process data in parallel. The Driver decides what work to do; executors do the work and report back.
