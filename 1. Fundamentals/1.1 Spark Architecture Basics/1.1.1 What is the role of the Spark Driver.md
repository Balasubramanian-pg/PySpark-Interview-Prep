# 1.1.1 What is the role of the Spark Driver?

### The Role of the Spark Driver

The Spark Driver is the process that runs your application’s `main()` function and coordinates the whole Spark job. It is the “brain” of the application: it plans the work, schedules it, and collects the final result. It does not do the heavy data processing itself.

- **Runs your code**: It executes the `main()` function and creates the `SparkContext` or `SparkSession`.
- **Builds the execution plan**: It reads your transformations and actions and decides how the work should be split.
- **Requests resources**: It talks to the Cluster Manager to get executors.
- **Schedules tasks**: It splits work into tasks and sends them to executors.
- **Tracks progress**: It monitors tasks, handles failures, and coordinates recovery.
- **Collects results**: When an action such as `collect()` or `count()` runs, the driver receives the final result.

> [!IMPORTANT]
> The driver is a single process. It plans and coordinates work, but the actual parallel computation is done by executors on worker nodes.

> [!WARNING]
> Actions like `collect()` bring data back to the driver. If the dataset is very large, this can cause an out-of-memory error on the driver.

### Clear Definitions

- **Driver**: The process that runs your `main()` function, creates the Spark session, plans jobs, schedules tasks, and collects results.
- **Executor**: A worker process on a cluster node that runs tasks and stores data.
- **Cluster Manager**: A service such as YARN, Kubernetes, or Spark Standalone that allocates resources to Spark applications.
- **Job**: A unit of work triggered by one action, such as `count()` or `saveAsTextFile()`.
- **Stage**: A part of a job that can run without moving data across the network. Jobs are split into stages at shuffle boundaries.
- **Task**: The smallest unit of work. A task usually processes one partition of data.
- **Transformation**: An operation that creates a new dataset from an existing one, such as `map()` or `filter()`. Transformations are lazy.
- **Action**: An operation that triggers computation and returns a result, such as `collect()` or `count()`.

### Worked Example: Word Count

**Conceptual code**

```python
spark = SparkSession.builder.appName("WordCount").getOrCreate()

lines = spark.sparkContext.textFile("huge_log.txt")
words = lines.flatMap(lambda line: line.split(" "))
pairs = words.map(lambda word: (word, 1))
counts = pairs.reduceByKey(lambda a, b: a + b)

results = counts.collect()
```

**What the driver does step by step**

1. **Starts the application**: The driver runs the code and creates the `SparkSession`.
2. **Requests resources**: The driver contacts the Cluster Manager and asks for executors.
3. **Builds a lazy plan**: When `textFile`, `flatMap`, `map`, and `reduceByKey` are defined, the driver does not process data yet. It only builds a plan.
4. **Triggers a job**: When `collect()` is called, the driver starts real execution.
5. **Creates stages**: Because `reduceByKey` needs a shuffle, the driver splits the job into stages.
6. **Schedules tasks**: The driver splits each stage into tasks and sends them to executors.
7. **Coordinates execution**: Executors run the tasks in parallel and send results back to the driver.
8. **Returns the result**: The driver collects the final output and returns it to your program.

> [!NOTE]
> In local mode, the driver and executors run inside one JVM on one machine. The same code works, but there is no real distributed cluster.

In short: the driver is the manager of the Spark application. It plans, schedules, and coordinates the work, while executors perform the actual distributed computation.
