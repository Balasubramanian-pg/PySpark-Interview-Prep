# 1.1.4 What is a DAG (Directed Acyclic Graph) in Spark?

A DAG is Spark’s logical execution plan. It is a graph of the transformations you apply to data, where each node is a dataset or operation and each edge shows how data flows from one operation to the next. “Directed” means data flows one way; “acyclic” means there are no loops, so the plan cannot cycle back to an earlier step. Spark builds the DAG lazily and uses it to split work into stages and tasks when an action is called.
- **Represents transformations**: Each `map`, `filter`, `flatMap`, or `reduceByKey` becomes part of the DAG.
- **Is lazy**: The DAG is built when you write transformations, but nothing runs until an action such as `collect()` or `count()` is called.
- **Shows dependencies**: Edges show which operation depends on which dataset.
- **Helps Spark optimize**: Spark uses the DAG to plan stages, combine narrow transformations, and place shuffle boundaries.
- **Splits into stages**: The DAG is cut at shuffle boundaries. Each stage contains tasks that can run without moving data across the network.
- **Supports fault recovery**: If a partition is lost, Spark can use the DAG lineage to recompute only what is needed.
> [!IMPORTANT]
> A DAG is not the physical execution itself. It is the logical plan of transformations. The Driver converts the DAG into jobs, stages, and tasks when an action is triggered.
> [!NOTE]
> Narrow transformations such as `map` and `filter` usually stay in the same stage. Wide transformations such as `reduceByKey` and `groupByKey` require a shuffle and usually create a new stage.
> [!WARNING]
> A DAG must be acyclic. If the plan contained a cycle, Spark could not determine a safe execution order or a clear lineage for recovery.
### Clear Definitions
- **DAG**: A directed acyclic graph of data transformations and dependencies in a Spark application.
- **Transformation**: An operation that creates a new dataset from an existing one, such as `map()` or `filter()`. Transformations are lazy.
- **Action**: An operation that triggers execution and returns a result, such as `collect()` or `count()`.
- **Narrow transformation**: A transformation where each input partition contributes to at most one output partition, such as `map()`.
- **Wide transformation**: A transformation that requires data to be redistributed across partitions, such as `reduceByKey()`.
- **Shuffle**: The process of redistributing data across executors, usually between stages.
- **Stage**: A part of a job that can run without a shuffle boundary.
- **Lineage**: The record of how a dataset was built from its parent datasets, used for fault recovery.
### Worked Example: Word Count DAG
Code:
```python
lines = spark.sparkContext.textFile("huge_log.txt")
words = lines.flatMap(lambda line: line.split(" "))
pairs = words.map(lambda word: (word, 1))
counts = pairs.reduceByKey(lambda a, b: a + b)
results = counts.collect()
```
Step by step:
1. `textFile` creates the first node: the input dataset `lines`.
2. `flatMap` adds a node that splits lines into words.
3. `map` adds a node that turns each word into `(word, 1)`.
4. `reduceByKey` adds a node that aggregates counts by key. This is a wide transformation, so it needs a shuffle.
5. At this point, Spark has built a DAG but has not processed data, because all operations so far are lazy transformations.
6. When `collect()` is called, the Driver uses the DAG to create a job.
7. The Driver cuts the DAG at the `reduceByKey` shuffle boundary and creates two stages: a map stage and a reduce stage.
8. The map stage runs tasks for `flatMap` and `map`. The reduce stage runs tasks for `reduceByKey`.
9. Executors run the tasks, and the Driver collects the final counts.
In short: the DAG is Spark’s map of how data flows through your transformations. It lets Spark plan stages, schedule tasks, and recover from failures without rerunning the entire application.
