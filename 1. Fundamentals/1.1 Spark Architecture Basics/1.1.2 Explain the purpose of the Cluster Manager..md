# 1.1.2 Explain the purpose of the Cluster Manager.

<img width="1376" height="768" alt="image" src="https://github.com/user-attachments/assets/485a9b9e-e071-4e81-a8d4-fc01525af34f" />

The Cluster Manager is the resource manager for the cluster. Its main purpose is to allocate machines and resources to Spark applications and to start the processes Spark needs. It does not process data and does not schedule Spark tasks inside a job; the Spark Driver does that.
- **Allocates resources**: It gives CPU, memory, and containers or pods to Spark applications.
- **Starts executors**: When the Driver requests executors, the Cluster Manager finds free resources and launches executor processes on worker nodes.
- **Manages cluster nodes**: It tracks which machines are available, busy, or unhealthy.
- **Isolates applications**: It keeps resources for different applications separate so they do not interfere.
- **Releases resources**: When the application finishes, it returns resources to the cluster.
- **Works with the Driver**: The Driver asks for resources; the Cluster Manager grants them. The Driver then schedules tasks on the executors.

> [!IMPORTANT]
> The Cluster Manager allocates resources and launches executors. The Spark Driver plans jobs and schedules tasks. Executors run the tasks.

> [!NOTE]
> Common Cluster Managers are Spark Standalone, YARN, Kubernetes, and Mesos. In local mode, there is no real Cluster Manager because driver and executors run in one JVM.

> [!WARNING]
> If the Cluster Manager cannot allocate enough resources, the Spark application may wait, run slower, or fail to start executors.

### Clear Definitions
- **Cluster Manager**: A service that allocates cluster resources and launches executors for Spark applications.
- **Driver**: The process that runs the Spark application, plans jobs, and schedules tasks.
- **Executor**: A worker process that runs tasks and stores data.
- **Container or Pod**: A unit of resources allocated by the Cluster Manager.
- **Worker Node**: A machine in the cluster that can run executors.

### Worked Example: Word Count on a Cluster
1. The Driver starts and creates a `SparkSession`.
2. The Driver asks the Cluster Manager for executors, for example 4 executors with 2 cores each.
3. The Cluster Manager finds free worker nodes and launches 4 executor processes.
4. The Driver reads the lazy plan for `textFile`, `flatMap`, `map`, and `reduceByKey`.
5. When `collect()` is called, the Driver splits the job into stages and tasks.
6. The Driver sends tasks to the 4 executors.
7. The executors process data in parallel and send results back to the Driver.
8. The Driver returns the final result, and the Cluster Manager releases the executors.
In short: the Cluster Manager is the cluster’s resource supplier. It gives Spark the machines and executors it needs, while the Driver coordinates the actual Spark job.
