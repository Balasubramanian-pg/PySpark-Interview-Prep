# 1.3.3 What is the difference between a Transformation and an Action?

A **transformation** describes a new dataset derived from an existing one. It is lazy: it records the operation in the lineage DAG but does not process data. An **action** requests a result or writes data. It triggers the Driver to create a job, plan stages, and schedule tasks on executors.
- **Purpose**: Transformations define new RDDs or DataFrames. Actions return results to the Driver or write data to storage.
- **Evaluation**: Transformations are lazy and build a plan. Actions are eager and trigger execution.
- **Return value**: Transformations return a new distributed dataset. Actions return a local value, a collection, or a write status.
- **Examples of transformations**: `map()`, `filter()`, `flatMap()`, `select()`, `withColumn()`, `join()`, `groupBy()`, `reduceByKey()`.
- **Examples of actions**: `collect()`, `count()`, `first()`, `take()`, `show()`, `write()`, `foreach()`, `reduce()`.
- **Effect on the DAG**: Transformations add nodes to the DAG. Actions convert the DAG into a job with stages and tasks.
- **Fault recovery**: Transformations preserve lineage for recomputation. Actions consume the result; they do not change the source dataset.
> [!IMPORTANT]
> No action means no job and no data processing. Transformations only describe work; actions decide when that work actually runs.
> [!NOTE]
> Some operations look similar but differ by return type. `reduce()` is an action because it returns a single value. `reduceByKey()` is a transformation because it returns a new distributed dataset.
> [!WARNING]
> Calling an action on an uncached dataset may recompute the entire transformation chain. Multiple actions on the same data can cause repeated work unless you use `cache()` or `persist()`.
### Clear Definitions
- **Transformation**: A lazy operation that returns a new RDD or DataFrame from an existing one.
- **Action**: An operation that triggers computation and returns a result to the Driver or writes data.
- **Lazy evaluation**: Delaying computation until an action is called.
- **Lineage**: The record of transformations used to build a dataset.
- **DAG**: The directed acyclic graph of transformations and dependencies.
- **Job**: The computation triggered by one action.
- **Stage**: A shuffle-separated part of a job.
- **Task**: The smallest unit of work, usually one partition in one stage.
### Worked Example: Transformation vs Action
Code:
```python
lines = sc.textFile("huge_log.txt")
words = lines.flatMap(lambda line: line.split(" "))
pairs = words.map(lambda word: (word, 1))
counts = pairs.reduceByKey(lambda a, b: a + b)
result = counts.collect()
```
Step by step:
1. `textFile` creates the first RDD. It is a transformation and is lazy.
2. `flatMap` is a transformation. It adds a node to the lineage but reads no data.
3. `map` is a transformation. It adds another node. Still no data is processed.
4. `reduceByKey` is a transformation. It adds a shuffle boundary to the DAG but does not run yet.
5. `collect()` is an action. Spark now creates a job from the DAG.
6. The Driver splits the job into stages at the `reduceByKey` shuffle and schedules tasks.
7. Executors run the transformations as tasks and return the final counts.
8. The Driver collects the result and returns it to your program.
In short: transformations build the plan lazily, and actions trigger the actual distributed computation. The same chain can be recomputed for each action unless the data is cached.
