### 1.3.4 Three examples of Transformations and three examples of Actions

Transformations are lazy and return a new dataset. Actions are eager and trigger computation to return a result or write data.

**Transformations (lazy, return a new RDD or DataFrame)**
- **`map()`**: Applies a function to each record and returns a new dataset. Example: `numbers.map(lambda x: x * 2)`.
- **`filter()`**: Keeps only records that satisfy a condition. Example: `df.filter(df.amount > 100)`.
- **`reduceByKey()`**: Combines values with the same key and returns a new key-value dataset. Example: `pairs.reduceByKey(lambda a, b: a + b)`.

**Actions (eager, trigger a job)**
- **`collect()`**: Returns all records to the Driver as a local list. Example: `counts.collect()`.
- **`count()`**: Returns the number of records as a single integer. Example: `df.count()`.
- **`write()`**: Writes the dataset to storage such as Parquet, CSV, or a database. Example: `df.write.parquet("output/")`.

> [!IMPORTANT]
> Transformations such as `map()`, `filter()`, and `reduceByKey()` only build the plan. Actions such as `collect()`, `count()`, and `write()` trigger the actual job.

> [!NOTE]
> `reduceByKey()` is a transformation because it returns a new distributed dataset. `reduce()` is an action because it returns a single local value.

> [!WARNING]
> Calling an action on an uncached dataset may recompute the entire transformation chain. Use `cache()` or `persist()` when you reuse the same data across multiple actions.

### Clear Definitions
- **Transformation**: A lazy operation that returns a new RDD or DataFrame from an existing one.
- **Action**: An operation that triggers computation and returns a result to the Driver or writes data.
- **Lazy evaluation**: Delaying computation until an action is called.
- **Job**: The computation triggered by one action.
- **Driver**: The process that plans jobs and collects results.

### Worked Example
Code:
```python
lines = sc.textFile("log.txt")
words = lines.flatMap(lambda line: line.split(" "))
pairs = words.map(lambda word: (word, 1))
counts = pairs.reduceByKey(lambda a, b: a + b)
total = counts.count()
counts.write.csv("output/")
```
Step by step:
1. `flatMap`, `map`, and `reduceByKey` are transformations. They build the lineage DAG but process no data.
2. `counts.count()` is an action. It triggers a job and returns the number of unique words as an integer.
3. `counts.write.csv(...)` is another action. It triggers a second job and writes the counts to storage.
4. Because `counts` is not cached, Spark may recompute the full chain for the second action.
In short: `map()`, `filter()`, and `reduceByKey()` are transformations that build the plan. `collect()`, `count()`, and `write()` are actions that trigger execution.
