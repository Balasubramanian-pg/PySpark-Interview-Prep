# 1.3.1 What is Lazy Evaluation in PySpark?

Lazy evaluation means PySpark does not process data when you write transformations. It records them in a plan or lineage DAG and waits until an action is called. Only then does the Driver create a job, stages, and tasks and send work to executors.
- **Transformations are lazy**: `map()`, `filter()`, `select()`, `withColumn()`, `join()`, and `groupBy()` only build a plan.
- **Actions trigger work**: `collect()`, `count()`, `show()`, `first()`, `take()`, and `write()` cause actual computation.
- **Plan is built first**: Spark records dependencies and can optimize the full chain before running anything.
- **Avoids unnecessary work**: If you build a transformation chain but never call an action, no data is read or processed.
- **Enables optimization**: Catalyst can rewrite DataFrame plans, push filters down, prune columns, and combine operations before execution.
- **Supports fault recovery**: The lineage DAG records how data was derived so lost partitions can be recomputed.
- **Caching is also lazy**: `cache()` and `persist()` mark data for reuse, but materialization happens on the first action that uses it.
> [!IMPORTANT]
> In PySpark, transformations describe what to compute. Actions decide when to compute. No action means no job and no data processing.
> [!NOTE]
> Lazy evaluation is not the same as no evaluation. Once an action runs, Spark may process all transformations needed for that action, and the same chain may rerun for a later action unless the data is cached.
> [!WARNING]
> Calling multiple actions on the same uncached DataFrame or RDD can recompute the entire chain each time. Use `cache()` or `persist()` when reusing the same data across actions.
### Clear Definitions
- **Lazy evaluation**: A strategy where computation is delayed until a result is actually needed.
- **Transformation**: An operation that returns a new RDD or DataFrame, such as `map()` or `filter()`. Transformations are lazy.
- **Action**: An operation that triggers computation and returns a result or writes data, such as `count()` or `write()`.
- **Lineage**: The record of transformations used to build a dataset, used for planning and recovery.
- **DAG**: The directed acyclic graph of transformations and dependencies.
- **Job**: The computation triggered by one action.
- **Caching or persistence**: Marking a dataset to be kept in memory or on disk after it is first computed.
### Worked Example: Lazy Evaluation in PySpark
Code:
```python
df = spark.read.csv("sales.csv", header=True)
filtered = df.filter(df.amount > 100)
selected = filtered.select("country", "amount")
print("No job has run yet")
result = selected.count()
print(result)
```
Step by step:
1. `spark.read.csv(...)` creates a DataFrame plan. No file is read yet.
2. `filter(...)` adds a filter node to the plan. No rows are processed.
3. `select(...)` adds a projection node. Still no computation.
4. The `print("No job has run yet")` line runs immediately because it is normal Python code.
5. `selected.count()` is an action. Spark now creates a job from the plan.
6. Catalyst optimizes the plan, for example by pushing the filter closer to the CSV scan and reading only needed columns.
7. The Driver schedules tasks, executors read and process the data, and the count is returned.
8. If you call `selected.count()` again without caching, Spark may recompute the whole chain.
In short: lazy evaluation means PySpark transformations only build a plan. Actions trigger the actual job. This lets Spark optimize the full chain and avoid work that is never needed.
