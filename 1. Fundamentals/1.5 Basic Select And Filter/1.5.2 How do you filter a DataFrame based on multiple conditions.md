# 1.5.2 How do you filter a DataFrame based on multiple conditions?

Use `df.filter()` or `df.where()` with conditions combined by logical operators. Wrap each condition in parentheses and join them with `&` (AND), `|` (OR), or `~` (NOT). You can also pass a single SQL expression string. Both `filter()` and `where()` are lazy transformations and are aliases of each other.

- **Use `&` for AND, `|` for OR, `~` for NOT**: These are the PySpark operators for combining conditions.
- **Parentheses are required**: Each condition must be wrapped in parentheses because `&` and `|` have lower precedence than comparison operators in Python.
- **Do not use `and` / `or` / `not`**: Python keywords do not work on Column objects and raise an error or produce wrong results.
- **Use `F.col()` or attribute access**: `df.amount > 100` and `F.col("amount") > 100` are equivalent. `F.col()` is safer when column names clash with DataFrame methods.
- **Combine with `filter()` and `where()`**: Both accept a Column expression or a SQL string such as `"amount > 100 AND country = 'IN'"`.
- **Use `.isin()` for list membership**: `df.country.isin("IN", "US")` is cleaner than chaining many OR conditions.
- **Use `.between()` for ranges**: `df.amount.between(100, 500)` means inclusive on both ends.
- **Use `.isNull()` / `.isNotNull()`**: Null comparisons with `== None` do not work in Spark SQL semantics.

> [!IMPORTANT]
> Always wrap each condition in parentheses before combining with `&` or `|`. Without parentheses, Python evaluates the expression in the wrong order and Spark raises a `Py4JError` or returns incorrect rows.

> [!WARNING]
> Do not use Python's `and`, `or`, and `not` on Column objects. They do not build Spark expressions. Use `&`, `|`, and `~` instead.

> [!NOTE]
> `filter()` and `where()` are aliases. Use whichever reads more clearly in your code. Neither triggers execution until an action such as `show()` or `count()` is called.

### Clear Definitions

- **`filter()`**: A lazy transformation that keeps only rows matching the given condition.
- **`where()`**: An alias of `filter()` with identical behavior.
- **`&`**: Bitwise AND operator used to combine two Spark Column conditions.
- **`|`**: Bitwise OR operator used to combine two Spark Column conditions.
- **`~`**: Bitwise NOT operator used to negate a Spark Column condition.
- **`F.col()`**: A function that returns a Column by name, useful when the column name clashes with a DataFrame attribute.
- **`isin()`**: A Column method that checks membership in a list of values.
- **`between()`**: A Column method that checks an inclusive range.
- **Null semantics**: In Spark SQL, comparisons involving null return null, so use `isNull()` and `isNotNull()` for null checks.

### Worked Example

Assume `df` has columns `id`, `country`, `amount`, and `status`.

```python
from pyspark.sql import functions as F

result = df.filter(
    (F.col("amount") > 100) &
    (F.col("country").isin("IN", "US")) &
    (F.col("status") != "cancelled") &
    (F.col("amount").between(100, 5000)) &
    (F.col("status").isNotNull())
)
result.show()
```

Step by step:
1. `F.col("amount") > 100` keeps rows above 100.
2. `F.col("country").isin("IN", "US")` keeps rows from India or the US.
3. `F.col("status") != "cancelled"` removes cancelled rows.
4. `F.col("amount").between(100, 5000)` keeps amounts in the inclusive range 100 to 5000.
5. `F.col("status").isNotNull()` removes rows with null status.
6. All conditions are joined with `&`, meaning a row must satisfy every condition.
7. Each condition is wrapped in parentheses so Python groups them correctly.
8. `show()` is an action and triggers the job. Catalyst pushes these filters toward the data source where possible.
9. To use OR instead of AND, replace `&` with `|` and keep the parentheses.
10. The equivalent SQL-string form is `df.where("amount > 100 AND country IN ('IN','US') AND status IS NOT NULL")`.

In short: combine conditions with `&`, `|`, and `~`, wrap each one in parentheses, and use `F.col()` for clarity. Prefer `isin()`, `between()`, and null-check methods over long chains of comparisons.
