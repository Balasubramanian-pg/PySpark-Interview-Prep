# 1.5.7 What is the difference between col('name') and df['name']?

### 1.5.7 Difference between col('name') and df['name']
- **Both return a Column object**: For a simple column reference, `col('name')` and `df['name']` produce the same unresolved column expression.
- **`col()` is a function**: It comes from `pyspark.sql.functions` and can be used without a DataFrame in scope.
- **`df['name']` uses `__getitem__`**: It is syntactic sugar on the DataFrame and requires a DataFrame object.
- **Same result in expressions**: `df.select(col('amount'))` and `df.select(df['amount'])` generate the same logical plan.
- **Different behavior with lists**: `df[['a','b']]` returns a DataFrame, not a Column. `col('a')` always returns a Column.
- **Name-clash safety**: `df['count']` is safe when a column name matches a DataFrame method. `df.count` would refer to the method.
- **Readability**: `col()` is explicit and common in complex expressions. `df['name']` is shorter for quick access.
- **Laziness**: Both are lazy and unresolved until used in a DataFrame operation that triggers analysis.
- **Case sensitivity**: Both follow the same column-name case rules.
> [!IMPORTANT]
> There is no performance difference. `col('name')` and `df['name']` both create a Column reference that Catalyst resolves against the DataFrame.
> [!WARNING]
> `df['name']` returns a Column, but `df[['name']]` returns a DataFrame. Do not confuse single-bracket column access with list-based selection.
> [!NOTE]
> `col()` requires `from pyspark.sql.functions import col`. `df['name']` requires no extra import.
### Clear Definitions
- **`col('name')`**: A function that returns a Column object referencing a column by name.
- **`df['name']`**: DataFrame indexing that returns a Column object for the named column.
- **Column object**: A lazy expression representing a column, used in `select()`, `filter()`, `withColumn()`, and similar operations.
- **Unresolved expression**: A column reference that Spark binds to a DataFrame schema during analysis.
- **DataFrame**: A distributed table with named columns and a schema.
### Worked Example
```python
from pyspark.sql import functions as F
a = df.select(F.col("amount"))
b = df.select(df["amount"])
a.explain(True)
b.explain(True)
```
Step by step:
1. `F.col("amount")` returns a Column referencing `amount`.
2. `df["amount"]` also returns a Column referencing `amount`.
3. `df.select(...)` builds a projection with that column.
4. `a.explain(True)` and `b.explain(True)` show the same analyzed and optimized plans.
5. Catalyst resolves the column against `df` in both cases.
6. No job runs until an action such as `a.show()` is called.
In short: `col('name')` and `df['name']` are equivalent for simple column references. Use `col()` for explicit, import-based expressions and `df['name']` for quick access. Remember that `df[['name']]` returns a DataFrame, not a Column.
