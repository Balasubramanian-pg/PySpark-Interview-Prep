# 1.2.1 What is an RDD and what are its key features?

An RDD (Resilient Distributed Dataset) is Spark’s fundamental distributed data abstraction. It is an immutable, partitioned collection of records that can be processed in parallel across executors. RDDs are created from data sources or by transforming existing RDDs, and they are evaluated lazily until an action is called.
- **Resilient**: Fault-tolerant through lineage. Lost partitions can be recomputed from the transformations that created them.
- **Distributed**: Data is split into partitions spread across executors in the cluster.
- **Dataset**: A collection of records, which can be objects, tuples, or key-value pairs.
- **Immutable**: You cannot change an RDD in place. Transformations return a new RDD.
- **Partitioned**: Each RDD has partitions, and each task usually processes one partition.
- **Lazy evaluation**: Transformations such as `map()` and `filter()` do not run immediately. Computation starts only when an action such as `collect()` or `count()` is called.
- **Lineage**: Each RDD remembers how it was built from parent RDDs, enabling recovery and recomputation.
- **In-memory capable**: You can cache or persist an RDD to reuse it across actions.
- **Parallel operations**: Transformations and actions run across partitions in parallel on executors.
> [!IMPORTANT]
> An RDD is immutable and lazy. Transformations build a lineage DAG, and actions trigger actual distributed computation.
> [!NOTE]
> Key-value RDDs support special operations such as `reduceByKey()`, `groupByKey()`, and `join()`. These often require a shuffle.
> [!WARNING]
> Caching an RDD can speed up reuse, but it consumes executor memory. If cached partitions are lost, Spark may recompute them from lineage unless the data is checkpointed or replicated.
### Clear Definitions
- **RDD**: An immutable, partitioned, distributed collection of records with lineage for fault tolerance.
- **Partition**: A logical chunk of an RDD that a task processes.
- **Transformation**: An operation that creates a new RDD from an existing one, such as `map()` or `filter()`. Transformations are lazy.
- **Action**: An operation that triggers computation and returns a result, such as `collect()` or `count()`.
- **Lineage**: The record of transformations used to build an RDD, used to recompute lost partitions.
- **Caching or persistence**: Storing an RDD’s partitions in memory or on disk for reuse.
- **Shuffle**: Redistribution of data across partitions, often needed for key-based operations.
### Worked Example: Word Count with RDDs
Code:
```python
lines = sc.textFile("huge_log.txt")
words = lines.flatMap(lambda line: line.split(" "))
pairs = words.map(lambda word: (word, 1))
counts = pairs.reduceByKey(lambda a, b: a + b)
results = counts.collect()
```
Step by step:
1. `sc.textFile(...)` creates the first RDD, `lines`. It is partitioned and lazy.
2. `flatMap(...)` creates a new RDD, `words`. Each input partition produces word records.
3. `map(...)` creates a new RDD, `pairs`, with `(word, 1)` records.
4. `reduceByKey(...)` creates a new key-value RDD, `counts`. It needs a shuffle because records with the same key must be brought together.
5. No data has been processed yet because all these operations are transformations.
6. `collect()` is an action. Spark builds a job from the RDD lineage and schedules tasks on partitions.
7. Executors process partitions in parallel, write shuffle data, and compute the final counts.
8. The Driver collects the results and returns them to your program.
In short: an RDD is a lazy, immutable, partitioned dataset with lineage. Transformations build new RDDs, and actions trigger parallel computation across the cluster.
