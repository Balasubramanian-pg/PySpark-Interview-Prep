# 1.2.3 Explain the concept of Immutability in Spark data structures.

Immutability means that once an RDD, DataFrame, or Dataset is created, its data cannot be changed in place. Any transformation such as `map()`, `filter()`, or `withColumn()` returns a new data structure and leaves the original unchanged. Spark records how the new structure was built from the old one, which supports safe parallel processing and fault recovery.
- **No in-place changes**: You cannot modify individual records or partitions of an existing RDD or DataFrame.
- **Transformations create new structures**: `map()`, `filter()`, `select()`, and `withColumn()` return a new RDD or DataFrame.
- **Original stays reusable**: The original RDD or DataFrame remains valid and can be used by other computations.
- **Lineage is preserved**: Each new structure remembers its parent and the transformation applied, forming a lineage DAG.
- **Fault tolerance**: If a partition is lost, Spark can recompute it from the immutable parent data and recorded transformations.
- **Safe parallelism**: Executors can read the same partitions without locking because no one can modify them.
- **Predictable caching**: Cached or persisted data is stable. Spark does not have to worry about another operation changing it.
- **Actions do not mutate the source**: Actions such as `count()` or `collect()` compute results but do not change the original data structure.
> [!IMPORTANT]
> In Spark, transformations are declarative and immutable. They describe a new dataset derived from an old one. They do not edit the old dataset.
> [!NOTE]
> Immutability is a major reason Spark can recompute lost partitions safely. The lineage records the exact transformations needed to rebuild any derived dataset.
> [!WARNING]
> Immutability does not mean data is never written to disk or memory. Caching, shuffling, and checkpointing write data, but they do not change the logical contents of the original RDD or DataFrame.
### Clear Definitions
- **Immutability**: The property that an object’s data cannot be changed after creation.
- **Transformation**: An operation that returns a new distributed dataset from an existing one, such as `map()` or `filter()`.
- **Lineage**: The record of transformations used to build a dataset from its parents.
- **RDD**: An immutable, partitioned, distributed collection of records.
- **DataFrame**: An immutable distributed table with named columns and a schema.
- **Action**: An operation that triggers computation and returns a result, such as `count()` or `collect()`.
- **Partition**: A logical chunk of a distributed dataset that a task processes.
### Worked Example: Immutability with RDDs
Code:
```python
numbers = sc.parallelize([1, 2, 3, 4])
doubled = numbers.map(lambda x: x * 2)
evens = doubled.filter(lambda x: x % 4 == 0)

print(numbers.collect())
print(doubled.collect())
print(evens.collect())
```
Step by step:
1. `numbers` is created as an RDD with values `[1, 2, 3, 4]`.
2. `numbers.map(...)` does not change `numbers`. It returns a new RDD, `doubled`.
3. `doubled.filter(...)` does not change `doubled`. It returns another new RDD, `evens`.
4. `numbers.collect()` still returns `[1, 2, 3, 4]` because the original RDD was never modified.
5. `doubled.collect()` returns `[2, 4, 6, 8]`.
6. `evens.collect()` returns `[4, 8]`.
7. Spark can recompute any of these RDDs from the original `numbers` RDD and the recorded transformations if a partition is lost.
### Worked Example: Immutability with DataFrames
Code:
```python
df = spark.createDataFrame([(1, "a"), (2, "b")], ["id", "value"])
df2 = df.withColumn("id_doubled", df.id * 2)
df3 = df2.filter(df2.id_doubled > 2)
```
Step by step:
1. `df` is created with columns `id` and `value`.
2. `df.withColumn(...)` returns a new DataFrame, `df2`. The original `df` is unchanged.
3. `df2.filter(...)` returns another new DataFrame, `df3`.
4. `df` still has only `id` and `value`. It does not gain `id_doubled`.
5. Spark can optimize the chain of immutable transformations using Catalyst before execution.
In short: Spark data structures are immutable. Transformations create new RDDs or DataFrames, preserve the originals, and record lineage. This makes parallel processing safe, enables fault recovery, and keeps computations predictable.
