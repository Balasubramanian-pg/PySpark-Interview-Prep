# 1.2.5 What is the difference between DataFrames and Datasets?

A DataFrame is a distributed table with named columns and a schema. It is untyped from the API perspective: columns are accessed by name or expression, and type errors often appear at runtime. A Dataset is a typed distributed collection in Scala and Java. It provides compile-time type safety and uses Encoders to convert JVM objects to Spark’s internal format. In the JVM, a DataFrame is effectively `Dataset[Row]`, so DataFrames are a special case of Datasets.
- **Type safety**: Datasets are typed and checked at compile time in Scala and Java. DataFrames are untyped and checked mostly at runtime.
- **API style**: Datasets combine relational operations with typed functional operations such as `map`, `filter`, and `groupByKey`. DataFrames focus on SQL-like operations such as `select`, `where`, and `groupBy`.
- **Schema handling**: DataFrames always carry a schema with named columns. Datasets map the schema to a Scala or Java class.
- **Encoders**: Datasets use Encoders for efficient conversion between JVM objects and Spark’s binary format. DataFrames use `Row` objects and the schema.
- **Language support**: DataFrames are available in Scala, Java, Python, and R. Datasets are available only in Scala and Java. PySpark has DataFrames, not typed Datasets.
- **Optimization**: Both go through Catalyst and Tungsten. Neither is automatically faster just because it is a Dataset.
- **Flexibility**: DataFrames are easier for dynamic schemas, SQL, and exploratory work. Datasets are better when you want strong typing and domain objects in Scala or Java.
- **Relationship**: `DataFrame = Dataset[Row]` in the JVM. A DataFrame is an untyped Dataset.
> [!IMPORTANT]
> The main difference is typed versus untyped. Datasets give compile-time type safety in Scala and Java. DataFrames give a schema-based, untyped table API available in all Spark languages.
> [!NOTE]
> In PySpark, there is no typed Dataset API. You use DataFrames. Accessing `df.rdd` gives an RDD, but that loses Catalyst and Tungsten benefits for subsequent operations.
> [!WARNING]
> Datasets are not automatically faster than DataFrames. Both use Catalyst and Tungsten. Choose Datasets for type safety and domain objects in Scala or Java, not because you expect a performance guarantee.
### Clear Definitions
- **DataFrame**: An untyped distributed table with named columns and a schema, available across Spark languages.
- **Dataset**: A typed distributed collection available in Scala and Java, with compile-time type safety and Encoders.
- **Row**: A generic row object used by DataFrames to hold column values without a specific Scala or Java type.
- **Encoder**: A component that converts JVM objects to and from Spark’s internal binary representation.
- **Typed API**: An API where the compiler checks the types of records and operations.
- **Untyped API**: An API where records are generic rows and column types are checked mainly at runtime.
- **Catalyst**: Spark SQL’s query optimizer, used by both DataFrames and Datasets.
- **Tungsten**: Spark’s execution engine for memory management and generated code, used by both.
### Worked Example: DataFrame vs Dataset in Scala
DataFrame version:
```scala
val df = spark.read.json("people.json")
val adults = df.filter(df("age") > 18).select("name", "age")
adults.show()
```
Dataset version:
```scala
case class Person(name: String, age: Long)
val ds = spark.read.json("people.json").as[Person]
val adults = ds.filter(p => p.age > 18).map(p => (p.name, p.age))
adults.show()
```
Step by step:
1. The DataFrame version uses column names and expressions. A wrong column name or incompatible type is usually caught at runtime.
2. The Dataset version maps rows to `Person` objects. The compiler checks that `p.age` exists and is numeric.
3. In the Dataset version, `map(p => ...)` uses typed JVM objects and Encoders convert them to Spark’s internal format.
4. Both versions are optimized by Catalyst and executed with Tungsten.
5. In PySpark, only the DataFrame style is available. There is no typed `Dataset[Person]` equivalent.
In short: DataFrames are untyped tables available in all Spark languages. Datasets are typed collections in Scala and Java with compile-time safety and Encoders. A DataFrame is `Dataset[Row]`, and both share the same optimizer and execution engine.
