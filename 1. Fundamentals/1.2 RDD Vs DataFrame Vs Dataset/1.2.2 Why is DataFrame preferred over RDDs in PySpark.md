# 1.2.2 Why is DataFrame preferred over RDDs in PySpark?

A DataFrame is a structured, table-like abstraction with named columns and a schema. It runs on top of RDDs but adds an optimizer and a faster execution engine. In PySpark, DataFrames are usually preferred because they are faster, easier to write, and better optimized for structured data.
- **Catalyst optimizer**: DataFrames pass through Catalyst, which rewrites and optimizes the query plan. RDDs have no such optimizer.
- **Tungsten execution**: DataFrames use Tungsten for efficient memory management and generated code. RDDs rely on JVM objects and generic execution.
- **Schema awareness**: DataFrames know column names and types. This enables better planning, fewer errors, and easier column-based operations.
- **Less Python serialization overhead**: RDD operations in PySpark often serialize Python objects between JVM and Python workers. DataFrames use a more efficient columnar path.
- **Higher-level API**: You can use `select`, `filter`, `groupBy`, `join`, and SQL-like expressions instead of writing low-level lambda functions.
- **Automatic optimization of joins and filters**: Catalyst can push filters down, reorder joins, and prune columns. RDD code runs exactly as written.
- **Better for structured and semi-structured data**: CSV, JSON, Parquet, and tables fit naturally into DataFrames.
- **Easier to maintain**: DataFrame code is usually shorter and more readable than equivalent RDD code.
- **Still lazy**: DataFrames are lazy like RDDs. They build a plan and execute only when an action such as `show()`, `count()`, or `collect()` is called.
- **RDDs are still useful for low-level control**: Use RDDs when you need fine-grained control over partitions, custom serialization, or unstructured data that does not fit a schema.
> [!IMPORTANT]
> DataFrames are preferred for structured data because Catalyst and Tungsten optimize the work before execution. RDDs give control but do not get these automatic optimizations.
> [!NOTE]
> A DataFrame is built on top of RDDs internally. You can still access the underlying RDD with `df.rdd`, but doing so usually loses the Catalyst and Tungsten benefits.
> [!WARNING]
> DataFrames are not always better. If your data is highly unstructured, or you need custom partition-level logic, an RDD may be the right choice. Also, PySpark DataFrames are not compile-time type-safe like Scala Datasets; schema errors often appear at runtime.
### Clear Definitions
- **RDD**: An immutable, partitioned, distributed collection of records with lineage. It is low-level and has no schema.
- **DataFrame**: A distributed table with named columns and a schema, backed by an optimized query planner.
- **Schema**: The column names and data types of a structured dataset.
- **Catalyst**: Spark SQL’s query optimizer that rewrites logical plans into efficient physical plans.
- **Tungsten**: Spark’s execution engine for memory management and generated code.
- **Lazy evaluation**: Work is planned first and executed only when an action is called.
- **Action**: An operation that triggers computation, such as `count()` or `collect()`.
### Worked Example: Word Count in RDD vs DataFrame
RDD version:
```python
lines = sc.textFile("huge_log.txt")
words = lines.flatMap(lambda line: line.split(" "))
pairs = words.map(lambda word: (word, 1))
counts = pairs.reduceByKey(lambda a, b: a + b)
results = counts.collect()
```
DataFrame version:
```python
from pyspark.sql.functions import explode, split
df = spark.read.text("huge_log.txt")
words = df.select(explode(split(df.value, " ")).alias("word"))
counts = words.groupBy("word").count()
results = counts.collect()
```
Step by step:
1. The RDD version sends Python lambdas to executors and has no schema. Spark runs the operations as written.
2. The DataFrame version has a schema and a logical plan.
3. Catalyst can optimize the DataFrame plan, for example by pruning columns and choosing efficient aggregation.
4. Tungsten executes the optimized plan with better memory handling.
5. Both versions are lazy until `collect()` is called.
6. For structured data and SQL-like work, the DataFrame version is usually faster and easier to maintain.
In short: DataFrames are preferred in PySpark because Catalyst and Tungsten optimize structured work, the API is higher-level, and Python serialization overhead is lower. RDDs remain useful when you need low-level control or work with unstructured data.
