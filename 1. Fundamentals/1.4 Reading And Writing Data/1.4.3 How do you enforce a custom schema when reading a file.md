# 1.4.3 How do you enforce a custom schema when reading a file?

### 1.4.3 How to enforce a custom schema when reading a file
Define an explicit `StructType` with `StructField` entries for each column, then pass it to `spark.read` using the `schema=` parameter. Spark uses your declared names and types directly and skips inference entirely. You can define the schema in Python, use a DDL string, or read it from a JSON file.
- **Build a `StructType`**: Create a schema by listing `StructField(name, dataType, nullable)` for every column.
- **Pass it with `schema=`**: Use `spark.read.csv(path, header=True, schema=schema)` or the equivalent for JSON and Parquet.
- **Use DDL strings for brevity**: A DDL string like `"order_id INT, country STRING, amount DOUBLE"` is shorter than building `StructField` objects.
- **Load a schema from JSON**: Save a schema with `df.schema.json()` and reload it with `StructType.fromJson()`, useful for reuse across pipelines.
- **Skip inference entirely**: An explicit schema avoids the extra scan and the risk of wrong inferred types.
- **Control nullability**: Set `nullable=False` when a column must never be null. Spark may fail or drop rows if the data violates this, depending on the mode.
- **Choose a parse mode**: Use `mode="PERMISSIVE"` (default), `"DROPMALFORMED"`, or `"FAILFAST"` to control how malformed rows are handled.
- **Reuse the schema across reads**: Define it once and pass it to every read of the same dataset for consistency and speed.
> [!IMPORTANT]
> An explicit schema is the recommended approach for production pipelines. It is faster than inference, avoids silent type errors, and makes the pipeline’s expected structure explicit and reviewable.
> [!NOTE]
> When `header=True` is set, the header row is still read and used for display, but the column names in your schema take precedence. If the header and schema disagree, the schema wins and the header may be ignored or cause an error depending on settings.
> [!WARNING]
> With `mode="FAILFAST"`, a single malformed row fails the entire job. With `mode="DROPMALFORMED"`, bad rows are silently dropped, which can hide data quality problems. Choose the mode deliberately.
### Clear Definitions
- **`StructType`**: Spark’s class for a schema, holding an ordered list of `StructField` entries.
- **`StructField`**: A single column definition with a name, data type, and nullability flag.
- **DDL string**: A short text representation of a schema, such as `"id INT, name STRING"`.
- **Parse mode**: A setting that controls how malformed rows are handled: `PERMISSIVE`, `DROPMALFORMED`, or `FAILFAST`.
- **Nullability**: Whether a column is allowed to contain null values.
- **`schema=` parameter**: The DataFrameReader option that accepts an explicit schema.
### Worked Example: Three Ways to Enforce a Custom Schema
**1. Python `StructType`**
```python
from pyspark.sql.types import StructType, StructField, IntegerType, StringType, DoubleType
schema = StructType([
    StructField("order_id", IntegerType(), False),
    StructField("country", StringType(), True),
    StructField("amount", DoubleType(), True),
])
df = spark.read.csv("sales.csv", header=True, schema=schema, mode="FAILFAST")
df.printSchema()
```
**2. DDL string**
```python
ddl = "order_id INT NOT NULL, country STRING, amount DOUBLE"
df = spark.read.csv("sales.csv", header=True, schema=ddl)
```
**3. Schema from JSON**
```python
# Save once
df.schema.json()  # e.g. '{"type":"struct","fields":[...]}'
# Reload later
from pyspark.sql.types import StructType
schema = StructType.fromJson(json.loads(saved_json))
df = spark.read.csv("sales.csv", header=True, schema=schema)
```
Step by step:
1. **Define the schema**: Each method declares column names and types explicitly.
2. **Pass it to the reader**: `schema=schema` tells Spark to use these types instead of inferring them.
3. **Set the parse mode**: `FAILFAST` makes any row that does not match the schema fail the job, which is useful for strict pipelines.
4. **Skip inference**: Spark reads the file once and applies the declared types directly, avoiding the inference scan.
5. **Enforce nullability**: `order_id` is declared `False`, so a null in that column triggers a failure under `FAILFAST`.
6. **Reuse the schema**: Save and reload it with `df.schema.json()` and `StructType.fromJson()` for consistency across jobs.
7. **Read the data**: `df.printSchema()` confirms the enforced schema, and downstream operations rely on the declared types.
In short: define a `StructType`, a DDL string, or a saved JSON schema and pass it with `schema=`. This skips inference, enforces exact types and nullability, and lets you choose how malformed rows are handled.
