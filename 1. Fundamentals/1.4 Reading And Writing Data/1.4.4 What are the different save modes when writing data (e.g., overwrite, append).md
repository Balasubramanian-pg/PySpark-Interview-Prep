# 1.4.4 What are the different save modes when writing data (e.g., overwrite, append)?

### 1.4.4 Different save modes when writing data
Save modes control what Spark does when the target output path or table already exists. In PySpark, set the mode with `df.write.mode(...)` before calling `.save()`, `.parquet()`, `.csv()`, or `.insertInto()`. The four standard modes are `error`/`errorifexists`, `overwrite`, `append`, and `ignore`.
- **`error` or `errorifexists` (default)**: Fails the write if the target already exists. This is the safest default because it prevents accidental data changes.
- **`overwrite`**: Deletes or replaces the existing target data, then writes the new data. Use with caution because old data is lost.
- **`append`**: Adds the new data to the existing target without removing old data. This can create duplicates if the same data is written twice.
- **`ignore`**: Does nothing if the target already exists. The write is skipped silently, which can hide mistakes if you expected new data.
- **Mode is set before the write action**: `df.write.mode("append").parquet(path)` applies the mode to that write only.
- **Behavior depends on the sink**: File-based sinks and table sinks follow the same mode names, but partitioned overwrites may replace only affected partitions depending on Spark and table format settings.
> [!IMPORTANT]
> The default save mode is `error`/`errorifexists`. Spark will fail rather than overwrite or append unless you explicitly choose another mode.
> [!WARNING]
> `overwrite` deletes existing data at the target. A mistaken overwrite can destroy production data. Use it only when replacing the dataset is intentional.
> [!NOTE]
> `ignore` does not tell you that it skipped the write. If you expect fresh data, `ignore` can leave stale data in place without any error.
### Clear Definitions
- **Save mode**: A setting that decides how Spark handles an existing output target during a write.
- **`errorifexists`**: The default mode. Fails if the target exists.
- **`overwrite`**: Replaces existing data with new data.
- **`append`**: Adds new data to existing data.
- **`ignore`**: Skips the write if the target exists.
- **DataFrameWriter**: The object returned by `df.write` that configures and performs writes.
- **Target**: The output path, table, or location being written to.
### Worked Example: Writing sales data in each mode
Assume `df` contains new sales rows and `output/sales` already exists with old rows.
```python
df.write.mode("errorifexists").parquet("output/sales")  # fails because target exists
df.write.mode("overwrite").parquet("output/sales")      # old data replaced by new data
df.write.mode("append").parquet("output/sales")         # new rows added to old rows
df.write.mode("ignore").parquet("output/sales")         # write skipped, old data remains
```
Step by step:
1. `errorifexists` checks that `output/sales` exists and raises an error. No data is changed.
2. `overwrite` removes or replaces the existing `output/sales` contents and writes only the new rows.
3. `append` keeps the old rows and adds the new rows. If the same rows were written before, duplicates may appear.
4. `ignore` sees that `output/sales` exists and does nothing. The old data remains unchanged and no error is raised.
5. The chosen mode applies only to that write call. A later write can use a different mode.
In short: `errorifexists` fails on existing targets, `overwrite` replaces them, `append` adds to them, and `ignore` skips the write. Choose the mode deliberately because each one has different data-safety consequences.
