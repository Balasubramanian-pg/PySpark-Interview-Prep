# 1.4.7 How do you read data from a relational database using JDBC?

To read data from a relational database into a PySpark DataFrame, use `spark.read.jdbc()` or the equivalent `spark.read.format("jdbc")` syntax. This lets Spark connect to the database and pull data in parallel, which is essential for performance on large tables.

### Basic syntax and core options
The fundamental approach involves specifying the JDBC URL, the table name, and your connection credentials.
- **URL**: The JDBC connection string, for example `jdbc:postgresql://host:port/database`.
- **Table**: The name of the table or a subquery to read.
- **Properties**: A dictionary containing `user` and `password` for authentication.
- **Driver**: You may need to specify the JDBC driver class if Spark cannot auto-detect it.

```python
jdbc_url = "jdbc:postgresql://localhost:5432/mydb"
connection_properties = {
    "user": "my_user",
    "password": "my_password",
    "driver": "org.postgresql.Driver"
}
df = spark.read.jdbc(
    url=jdbc_url,
    table="my_table",
    properties=connection_properties
)
```

### Parallel reading (key performance options)
By default, a single JDBC read uses only one task, which can be very slow for large tables. To enable parallel reads, specify four interconnected options that tell Spark how to split the data across multiple partitions.
- **`partitionColumn`**: A numeric, date, or timestamp column used to split the data evenly. It must be a column in your table.
- **`lowerBound`**: The minimum value of the `partitionColumn` to start from (inclusive).
- **`upperBound`**: The maximum value of the `partitionColumn` to stop at (exclusive).
- **`numPartitions`**: The number of parallel partitions and therefore concurrent JDBC connections to create.

> [!IMPORTANT]
> These four options must be specified together. The `lowerBound` and `upperBound` are not filters. All rows in the table will be read, but the bounds determine how the range is divided into `numPartitions` strides for parallel reading.

```python
df = spark.read.jdbc(
    url=jdbc_url,
    table="large_sales_table",
    properties=connection_properties,
    partitionColumn="sale_id",
    lowerBound=1,
    upperBound=1000000,
    numPartitions=16
)
```

> [!WARNING]
> Do not set `numPartitions` too high. Each partition opens a concurrent connection to your database. An excessive number of parallel connections can overload or crash the external database system.

### Other performance options
- **`fetchSize`**: Controls how many rows are retrieved per round trip. For drivers like Oracle that default to a low fetch size, setting a higher value such as 1000 can significantly improve performance.
- **`predicates`**: An alternative to `partitionColumn`. You can provide a list of SQL `WHERE` clause expressions, and each expression defines one partition. This is useful for custom partitioning logic.
- **Subqueries**: Instead of a table name, you can provide a parenthesized SQL query such as `(SELECT * FROM table WHERE status = 'active') AS sub`. This allows you to filter or pre-aggregate data before it is pulled into Spark.

### Best practices and worked example
1. **Push down filters**: Use a subquery to filter data at the source. This reduces the volume of data transferred over the network.
2. **Choose a good partition column**: The `partitionColumn` should be evenly distributed, such as a primary key or an indexed numeric column, to avoid data skew across partitions.
3. **Secure credentials**: Avoid hardcoding passwords in your code. Use secret management tools or environment variables.
4. **Caching**: If you plan to reuse the JDBC DataFrame multiple times, consider calling `df.cache()` after reading to avoid re-querying the database for each action.

Worked example: reading a large `transactions` table with parallel partitions and a subquery filter.

```python
# Filter at the source and partition the read
subquery = "(SELECT * FROM transactions WHERE year = 2024) AS t"

df = spark.read.jdbc(
    url=jdbc_url,
    table=subquery,
    properties=connection_properties,
    partitionColumn="transaction_id",
    lowerBound=1,
    upperBound=50000000,
    numPartitions=32,
    fetchsize=1000
)

# Cache if the DataFrame will be reused
df.cache()
df.show(5)
```

In short, use `spark.read.jdbc()` with `user` and `password` properties for the connection, and add the four partition options (`partitionColumn`, `lowerBound`, `upperBound`, `numPartitions`) to enable parallel reads. Always ensure the JDBC driver JAR is available on the Spark classpath for both the driver and executors.
