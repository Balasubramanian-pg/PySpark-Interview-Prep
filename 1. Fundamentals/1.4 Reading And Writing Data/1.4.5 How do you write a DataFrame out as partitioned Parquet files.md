# 1.4.5 How do you write a DataFrame out as partitioned Parquet files?

Use `df.write.partitionBy(...).mode(...).parquet(path)`. Spark writes one directory per partition value combination and stores Parquet files inside those directories. Parquet is the default format for `df.write`, but calling `.parquet(path)` makes the intent explicit.
- **Choose partition columns**: Pick low-to-medium cardinality columns used in filters, such as `country` and `year`.
- **Set the write mode**: Use `overwrite`, `append`, `ignore`, or `errorifexists` deliberately.
- **Call `partitionBy`**: `df.write.partitionBy("country", "year").parquet("output/sales")`.
- **Understand the directory layout**: Spark creates paths like `output/sales/country=IN/year=2024/part-*.parquet`.
- **Partition columns are stored in paths**: By default, partition columns are not repeated inside the Parquet files; they are inferred from directory names on read.
- **Read it back**: `spark.read.parquet("output/sales")` restores the partition columns automatically.
- **Avoid high-cardinality partitions**: Partitioning by `order_id` or timestamps creates too many small directories and files.
- **Control file count**: Use `repartition()` or `coalesce()` before writing if you need fewer output files per partition.
> [!IMPORTANT]
> Partitioning improves read performance only when queries filter on the partition columns. Partitioning by columns that are rarely filtered adds overhead without benefit.
> [!WARNING]
> Too many partition columns or high-cardinality values create a large number of small files and directories. This stresses the file system and slows down reads and metadata operations.
> [!NOTE]
> For overwriting only affected partitions, Spark supports dynamic partition overwrite with `spark.sql.sources.partitionOverwriteMode=dynamic`. Without it, `overwrite` can replace the entire target.
### Clear Definitions
- **Partitioned write**: Writing data into separate directories based on column values.
- **`partitionBy`**: The DataFrameWriter method that selects partition columns.
- **Parquet**: A columnar file format optimized for analytics.
- **Partition column**: A column whose values determine the output directory structure.
- **High cardinality**: A large number of distinct values in a column.
- **Dynamic partition overwrite**: A mode where only partitions present in the new data are replaced.
### Worked Example
```python
df = spark.read.csv("sales.csv", header=True, inferSchema=True)
df.write \
  .mode("overwrite") \
  .partitionBy("country", "year") \
  .parquet("output/sales_partitioned")
read_back = spark.read.parquet("output/sales_partitioned")
read_back.printSchema()
```
Step by step:
1. `df` contains columns including `country` and `year`.
2. `mode("overwrite")` replaces any existing data at `output/sales_partitioned`.
3. `partitionBy("country", "year")` tells Spark to split output by these columns.
4. Spark writes directories such as `country=IN/year=2024/` and `country=US/year=2024/`.
5. Each directory contains one or more `part-*.parquet` files.
6. The `country` and `year` values are encoded in the directory names and are not repeated inside the files by default.
7. `spark.read.parquet(...)` reads the directory tree and restores `country` and `year` as columns.
8. A query such as `read_back.filter("country = 'IN'")` can skip unrelated directories through partition pruning.
In short: use `df.write.partitionBy("country", "year").parquet(path)` to create partitioned Parquet output. Choose low-cardinality filter columns, control file counts, and avoid high-cardinality partitions that create many small files.
