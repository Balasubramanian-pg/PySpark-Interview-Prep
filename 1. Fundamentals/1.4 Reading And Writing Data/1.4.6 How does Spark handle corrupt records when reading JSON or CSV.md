# 1.4.6 How does Spark handle corrupt records when reading JSON or CSV?

Spark uses a **parse mode** to decide what happens when a row does not match the expected schema or is malformed. The modes are `PERMISSIVE` (default), `DROPMALFORMED`, and `FAILFAST`. For JSON, `PERMISSIVE` can also capture the bad row in a special column set by `columnNameOfCorruptRecord`. CSV has no equivalent corrupt-record column; bad fields become null or the row is dropped depending on the mode.
- **`PERMISSIVE` (default)**: Spark sets unparseable or missing fields to `null` and keeps the rest of the row. For JSON, if `columnNameOfCorruptRecord` is set, the whole malformed record is stored in that column.
- **`DROPMALFORMED`**: Spark drops any row that cannot be parsed. This silently reduces your dataset and can hide data quality problems.
- **`FAILFAST`**: Spark raises an error as soon as it hits a malformed row and fails the job. This is the strictest mode.
- **JSON corrupt record column**: With `PERMISSIVE`, set `columnNameOfCorruptRecord="corrupt_record"` (or use the default `_corrupt_record`) to keep the raw bad row. This requires the schema to include that column.
- **CSV behavior**: In `PERMISSIVE`, a bad field becomes `null` and the row is kept. There is no built-in corrupt-record column for CSV.
- **Set the mode**: Use the `mode=` option with `spark.read.json(...)` or `spark.read.csv(...)`.
> [!IMPORTANT]
> The default parse mode is `PERMISSIVE`. Bad data does not stop the job by default; fields become null or the bad row is kept in a corrupt-record column for JSON. Use `FAILFAST` when data quality must be enforced.
> [!WARNING]
> `DROPMALFORMED` silently removes rows. If you do not track the input and output counts, you may not notice that data was lost. `PERMISSIVE` can also hide problems by turning bad values into nulls.
> [!NOTE]
> For JSON, the corrupt-record column must be part of the schema you provide. If you rely on inference and do not include it, Spark may not capture the raw bad record as expected.
### Clear Definitions
- **Parse mode**: A setting that controls how Spark handles malformed rows: `PERMISSIVE`, `DROPMALFORMED`, or `FAILFAST`.
- **`PERMISSIVE`**: Keeps bad rows, sets bad fields to null, and can store the raw bad JSON record in a corrupt-record column.
- **`DROPMALFORMED`**: Drops rows that cannot be parsed.
- **`FAILFAST`**: Fails the job on the first malformed row.
- **`columnNameOfCorruptRecord`**: The JSON option that names the column holding the raw malformed record.
- **Malformed record**: A row or field that does not match the expected schema or format.
### Worked Example: JSON with corrupt records
```python
schema = "id INT, name STRING, corrupt_record STRING"
df = spark.read \
    .option("mode", "PERMISSIVE") \
    .option("columnNameOfCorruptRecord", "corrupt_record") \
    .schema(schema) \
    .json("events.json")
df.show(truncate=False)
```
Step by step:
1. The schema includes `corrupt_record` so Spark has somewhere to store bad rows.
2. `PERMISSIVE` tells Spark to keep going when it hits a malformed row.
3. A valid row such as `{"id": 1, "name": "A"}` is parsed normally, and `corrupt_record` is null.
4. A malformed row such as `{"id": 2, "name":` is kept, and its raw text is placed in `corrupt_record`.
5. `show()` displays both good rows and the bad row with its raw content, so you can inspect and fix the source.
6. If you switched to `FAILFAST`, the job would stop at the malformed row.
7. If you switched to `DROPMALFORMED`, the malformed row would disappear from the result.
### Worked Example: CSV with a malformed field
```python
df = spark.read \
    .option("mode", "PERMISSIVE") \
    .schema("id INT, amount DOUBLE") \
    .csv("sales.csv")
df.show()
```
Step by step:
1. A row like `1,abc` has an `amount` that cannot be parsed as a double.
2. In `PERMISSIVE` mode, `amount` becomes null and the row is kept.
3. In `DROPMALFORMED` mode, the entire row is dropped.
4. In `FAILFAST` mode, the job fails at that row.
5. CSV has no corrupt-record column, so the raw bad value is not preserved unless you read the column as a string first and validate it yourself.
In short: Spark controls malformed JSON and CSV rows through the parse mode. `PERMISSIVE` keeps rows and can store bad JSON in a corrupt-record column, `DROPMALFORMED` drops bad rows, and `FAILFAST` fails the job. Choose the mode based on how strict your data quality requirements are.
