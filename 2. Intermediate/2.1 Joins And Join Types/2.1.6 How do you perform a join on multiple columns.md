# 2.1.6 How do you perform a join on multiple columns

Joining on multiple columns (composite keys) requires passing either a list of column names or a compound boolean condition. Getting this right is critical for accurately matching records like "user + date" without accidentally triggering massive data duplication or ambiguous reference errors.

### 0. Setup

```python
from pyspark.sql import SparkSession

spark = SparkSession.builder.getOrCreate()

# Left DataFrame: Daily Store Sales
sales_df = spark.createDataFrame([
    (1, "2023-10-01", 5000),
    (1, "2023-10-02", 6000),
    (2, "2023-10-01", 3000)
], ["store_id", "sale_date", "revenue"])

# Right DataFrame 1: Exact same column names (for Method 1)
inventory_same_df = spark.createDataFrame([
    (1, "2023-10-01", 100),
    (1, "2023-10-02", 150),
    (2, "2023-10-01", 50)
], ["store_id", "sale_date", "stock"])

# Right DataFrame 2: Different column names (for Method 2)
inventory_diff_df = spark.createDataFrame([
    (1, "2023-10-01", 100),
    (1, "2023-10-02", 150),
    (2, "2023-10-01", 50)
], ["store_id", "inv_date", "stock"])
```

### 1. Core Concept & Decision Tree (CRITICAL)

When dealing with composite keys, use this tree to pick the right syntax and avoid schema collisions.

```mermaid
graph TD
    A[Need to join on multiple columns] --> B{Are the join column names EXACTLY the same in both DataFrames?}
    B -- Yes --> C[Pass a list of strings: on=['col1', 'col2']]
    B -- No --> D[Pass a list of Column expressions: on=[df1.col1 == df2.colA, df1.col2 == df2.colB]]
```

### 2. Syntax & Implementation

```python
from pyspark.sql.functions import col

# Method 1: List of strings (Only works if column names match exactly)
# Spark automatically deduplicates these join keys in the output schema.
same_name_df = sales_df.join(
    inventory_same_df, 
    on=["store_id", "sale_date"], 
    how="inner"
)

# Method 2: List of Column expressions (Works when column names differ)
# CRITICAL: You MUST wrap the conditions in a list []. 
diff_name_df = sales_df.join(
    inventory_diff_df, 
    on=[
        sales_df.store_id == inventory_diff_df.store_id,
        sales_df.sale_date == inventory_diff_df.inv_date
    ],
    how="inner"
)

diff_name_df.show()
```

### 4. Interview Pro-Tips / Gotchas

*   **The "Missing Brackets" Trap:** If you pass multiple conditions without wrapping them in a list (e.g., `on=df1.a == df2.a, df1.b == df2.b`), Python will throw a syntax error, or if you use positional arguments incorrectly, Spark will misinterpret it. You *must* use a list: `on=[cond1, cond2]`. If you mess this up and only pass the first condition, you'll silently get a massive, incorrect join instead of a hard error.
*   **The Null Key Nightmare:** In Spark (and SQL), `null == null` evaluates to `false`. If your composite key contains nulls, those rows will silently fail to join. If you expect nulls in your keys, you need to use the null-safe equality operator (`<=>`) in your column expressions, or wrap your keys in `coalesce(col, "default_value")` before joining.
*   **First Principles (Hashing & Shuffles):** When you join on a single column, Spark hashes that column to determine which partition the row goes to. When you join on 5 columns, Spark has to compute a composite hash of all 5 columns. This increases CPU overhead for the hashing function and increases the network payload size during the shuffle. Keep your join keys as narrow as possible; if you're joining on a massive string column and an int, consider if you can pre-compute a single surrogate key to speed up the shuffle phase.
