# 2.1.2 What is a Left Semi Join and when would you use it?

### What is a Left Semi Join?

A **Left Semi Join** is a type of join that returns rows from the left DataFrame **only if a match exists** in the right DataFrame. 

It is unique for two main reasons:
1. **It only returns columns from the left DataFrame.** The columns from the right DataFrame are completely ignored and dropped from the output.
2. **It does not duplicate rows.** If a single row in the left DataFrame matches *multiple* rows in the right DataFrame, the left row is still only returned **once**. 

In standard SQL, a Left Semi Join is equivalent to using an `IN` or `EXISTS` subquery.

---

### When would you use it?

You should use a Left Semi Join when you want to **filter** a DataFrame based on the existence of keys in another DataFrame, without actually bringing over any data from that second DataFrame.

Here are the most common scenarios:

#### 1. To avoid data duplication (One-to-Many relationships)
If you do a standard `inner` join between a "Customers" table and an "Orders" table to find out which customers have bought something, customers who made multiple purchases will show up multiple times in the result. A `left_semi` join guarantees that each matching customer will only appear once in your result set.

#### 2. Filtering based on a master list or reference table
If you have a massive dataset of web logs and you only want to keep logs for users who exist in your active `subscribers_df`, you can do a left semi join. 

#### 3. Performance Optimization
Because a semi join only checks for *existence*, the Spark engine can optimize the query. As soon as Spark finds the *first* match in the right table, it stops looking for that specific key. It doesn't need to shuffle and join all the subsequent matches, making it faster and more memory-efficient than an inner join followed by a `.dropDuplicates()`.

---

### Code Example: Left Semi Join vs. Inner Join

Let's look at a scenario with Customers and Orders to see why Left Semi Join is so useful.

```python
from pyspark.sql import SparkSession

spark = SparkSession.builder.appName("LeftSemiJoin").getOrCreate()

# 1. Create Customers DataFrame (Left)
customers_data = [
    (1, "Alice"), 
    (2, "Bob"), 
    (3, "Charlie")  # Charlie has no orders
]
customers_df = spark.createDataFrame(customers_data, ["customer_id", "name"])

# 2. Create Orders DataFrame (Right)
# Notice Alice (1) has TWO orders.
orders_data = [
    (101, 1, "Laptop"), 
    (102, 1, "Mouse"), 
    (103, 2, "Monitor")
]
orders_df = spark.createDataFrame(orders_data, ["order_id", "customer_id", "product"])
```

#### What happens with an Inner Join?
If we just want a list of customers who placed an order, an inner join causes a problem: Alice is duplicated.

```python
# Inner Join
inner_df = customers_df.join(orders_df, on="customer_id", how="inner")
inner_df.show()

# Output:
# +-----------+-----+--------+-------+
# |customer_id| name|order_id|product|
# +-----------+-----+--------+-------+
# |          1|Alice|     101| Laptop| <-- Alice appears twice!
# |          1|Alice|     102|  Mouse|
# |          2|  Bob|     103|Monitor|
# +-----------+-----+--------+-------+
```

#### What happens with a Left Semi Join?
The Left Semi Join acts as an existence check. It solves the duplication problem and only returns the customer columns.

```python
# Left Semi Join
semi_df = customers_df.join(orders_df, on="customer_id", how="left_semi")
semi_df.show()

# Output:
# +-----------+-----+
# |customer_id| name|
# +-----------+-----+
# |          1|Alice| <-- Alice appears only once.
# |          2|  Bob|
# +-----------+-----+
# Note: Charlie is missing because he has no orders. 
# Note: "order_id" and "product" columns are not in the output.
```
