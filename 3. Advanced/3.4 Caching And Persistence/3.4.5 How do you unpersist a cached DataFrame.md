# 3.4.5 How do you unpersist a cached DataFrame?

### 3.4.5 How do you unpersist a cached DataFrame

To unpersist a cached DataFrame, call the `unpersist()` method on the DataFrame. This removes its cached blocks from memory and disk across all executors. The DataFrame itself is not destroyed. It still has its lineage, so it can be recomputed from the original source if you perform another action. Unpersisting is important to release cluster resources for other operations.

**Basic unpersist for a DataFrame**

```python
df = spark.range(1000000)
df.cache()
df.count()  # triggers caching

# Remove cached data
df.unpersist()
```

**Unpersist for an RDD**

```python
rdd = sc.parallelize(range(1000000))
rdd.cache()
rdd.count()

rdd.unpersist()
```

**Blocking parameter**

In PySpark, `DataFrame.unpersist(blocking=False)` defaults to `False`. For RDDs, `RDD.unpersist(blocking=True)` defaults to `True`. The `blocking` parameter controls whether the call waits until all blocks are removed from memory and disk.

```python
# Wait until all cached blocks are removed
df.unpersist(blocking=True)

# Do not wait
df.unpersist(blocking=False)
```

**Unpersist using SQL**

If the DataFrame is registered as a temporary view or table, you can uncache it with SQL.

```python
df.createOrReplaceTempView("my_table")
df.cache()
spark.sql("SELECT * FROM my_table").count()

# Uncache using SQL
spark.sql("UNCACHE TABLE my_table")
```

**Unpersist using the catalog API**

```python
spark.catalog.uncacheTable("my_table")
```

**Clear all cached data**

To remove all cached tables and DataFrames from memory and disk, use `clearCache()`.

```python
spark.catalog.clearCache()
```

**Important notes**

- `unpersist()` is not lazy. It removes the cached blocks immediately when called.
- Calling `unpersist()` on a DataFrame that was never cached has no effect.
- After unpersisting, the DataFrame can still be used. Spark will recompute it from its lineage when needed.
- If you cached a DataFrame and then created a new DataFrame from it, unpersisting the original does not automatically unpersist the new one if it was also cached.
- Always unpersist when the cached data is no longer needed, especially in long-running applications, to avoid memory pressure and eviction of other useful data.
- In Spark 3.x, you can also use `spark.catalog.isCached("table_name")` to check whether a table is cached before unpersisting.

**Example: checking and unpersisting**

```python
df = spark.range(1000000)
df.createOrReplaceTempView("numbers")
df.cache()
df.count()

# Check if cached
print(spark.catalog.isCached("numbers"))  # True

# Unpersist
df.unpersist()

# Check again
print(spark.catalog.isCached("numbers"))  # False
```

**Summary**

To unpersist a cached DataFrame, call `df.unpersist()`. For RDDs, call `rdd.unpersist()`. You can control whether the call blocks with the `blocking` parameter. For SQL tables, use `UNCACHE TABLE` or `spark.catalog.uncacheTable()`. To clear all cached data, use `spark.catalog.clearCache()`. Unpersisting releases memory and disk resources and is a good practice when cached data is no longer needed.
