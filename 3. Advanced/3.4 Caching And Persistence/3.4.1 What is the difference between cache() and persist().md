# 3.4.1 What is the difference between cache() and persist()?
### 3.4.1 What is the difference between cache() and persist()

`cache()` and `persist()` are both used to store a DataFrame, Dataset, or RDD in memory or on disk so that it can be reused efficiently across multiple actions. The main difference is that `cache()` is a shorthand for `persist()` with a default storage level and does not accept arguments, while `persist()` allows you to specify a custom storage level.

**Default storage levels**

- For RDDs: `cache()` is equivalent to `persist(StorageLevel.MEMORY_ONLY)`. It stores data as deserialized Java objects in the JVM heap. If a partition does not fit in memory, it will be recomputed when needed.
- For DataFrames and Datasets: `cache()` is equivalent to `persist(StorageLevel.MEMORY_AND_DISK)`. It stores data in memory as deserialized objects, and if memory is insufficient, it spills partitions to disk. This is more robust for larger datasets.
- `persist()` without arguments uses the same default as `cache()` for the given dataset type. To use a different level, you must pass a `StorageLevel` explicitly.

**Available storage levels**

You can pass any of the following to `persist()`:

- `MEMORY_ONLY`
- `MEMORY_AND_DISK`
- `MEMORY_ONLY_SER`
- `MEMORY_AND_DISK_SER`
- `DISK_ONLY`
- `MEMORY_ONLY_2`
- `MEMORY_AND_DISK_2`
- `OFF_HEAP` (if configured)

The `_2` suffix means the data is replicated on two nodes. `_SER` means data is stored in serialized form, which saves memory but increases CPU usage.

**Lazy evaluation**

Both `cache()` and `persist()` are lazy. They only mark the dataset for caching. The actual caching happens when the first action (such as `count()`, `show()`, or `write()`) is executed. Until then, no data is stored.

**Unpersisting**

You can remove cached data with `unpersist()`. This releases the memory and disk resources. It is good practice to unpersist when the cached data is no longer needed, especially in long-running applications.

**Code examples in PySpark**

Caching an RDD with default level (MEMORY_ONLY):

```python
rdd = sc.parallelize(range(1000000))
rdd.cache()  # equivalent to rdd.persist(StorageLevel.MEMORY_ONLY)
rdd.count()  # triggers caching
rdd.unpersist()
```

Caching a DataFrame with default level (MEMORY_AND_DISK):

```python
df = spark.range(1000000)
df.cache()  # equivalent to df.persist(StorageLevel.MEMORY_AND_DISK)
df.count()  # triggers caching
df.unpersist()
```

Using persist with a custom storage level:

```python
from pyspark import StorageLevel

df = spark.range(1000000)
df.persist(StorageLevel.MEMORY_ONLY_SER)  # serialized in memory
df.count()
df.unpersist()
```

Persisting to disk only:

```python
df.persist(StorageLevel.DISK_ONLY)
df.count()
df.unpersist()
```

**When to use which**

- Use `cache()` when you want the default behavior and do not need to tune the storage level. It is concise and sufficient for most cases.
- Use `persist(StorageLevel.X)` when you need control over memory usage, serialization, replication, or disk spill. For example, if your data is too large for memory, use `MEMORY_AND_DISK` or `DISK_ONLY`. If you want to save memory at the cost of CPU, use a serialized level like `MEMORY_ONLY_SER`.

**Performance considerations**

- Caching can significantly speed up iterative algorithms and repeated queries on the same dataset.
- Caching consumes cluster resources. Over-caching can lead to out-of-memory errors or eviction of other useful data.
- Always unpersist when the cached data is no longer needed.
- For DataFrames, caching may change the physical plan and can sometimes prevent other optimizations. Use it judiciously.
- In Spark 3.x, Adaptive Query Execution (AQE) can sometimes make caching less necessary by optimizing shuffles and joins at runtime.

**Summary of differences**

| Feature | cache() | persist() |
|---------|---------|-----------|
| Arguments | None | StorageLevel (optional) |
| Default level (RDD) | MEMORY_ONLY | MEMORY_ONLY |
| Default level (DataFrame) | MEMORY_AND_DISK | MEMORY_AND_DISK |
| Custom level | No | Yes |
| Lazy | Yes | Yes |
| Unpersist | Yes | Yes |

In short, `cache()` is a convenient shortcut for `persist()` with the default storage level, while `persist()` gives you full control over how the data is stored. Use `cache()` for simplicity and `persist()` when you need to tune memory and disk usage.
