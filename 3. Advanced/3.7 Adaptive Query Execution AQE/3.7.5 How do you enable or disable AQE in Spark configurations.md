### 3.7.5 How do you enable or disable AQE in Spark configurations

Adaptive Query Execution (AQE) is controlled by the `spark.sql.adaptive.enabled` configuration property. In Spark 3.2.0 and later, AQE is enabled by default. To disable it, set the property to `false`. To explicitly enable it in versions where it may be off, or to ensure it is active, set it to `true`.

**Enabling AQE**

AQE is enabled by default in Spark 3.2+. If you are using an earlier Spark 3.x version or have explicitly disabled it, you can turn it back on by setting `spark.sql.adaptive.enabled` to `true`.

At SparkSession creation (PySpark):

```python
from pyspark.sql import SparkSession

spark = (SparkSession.builder
         .appName("AQEEnabledExample")
         .config("spark.sql.adaptive.enabled", "true")
         .getOrCreate())
```

At runtime (PySpark):

```python
spark.conf.set("spark.sql.adaptive.enabled", "true")
```

Using SQL:

```sql
SET spark.sql.adaptive.enabled=true;
```

Using spark-submit:

```bash
spark-submit --conf spark.sql.adaptive.enabled=true my_app.py
```

**Disabling AQE**

To disable AQE entirely, set `spark.sql.adaptive.enabled` to `false`. This also disables the adaptive query execution framework, including all sub-features such as partition coalescing, join strategy conversion, and skew join handling.

At SparkSession creation (PySpark):

```python
spark = (SparkSession.builder
         .appName("AQEDisabledExample")
         .config("spark.sql.adaptive.enabled", "false")
         .getOrCreate())
```

At runtime (PySpark):

```python
spark.conf.set("spark.sql.adaptive.enabled", "false")
```

Using SQL:

```sql
SET spark.sql.adaptive.enabled=false;
```

**Default value**

| Spark version | Default value of `spark.sql.adaptive.enabled` |
|---|---|
| Spark 3.0 and 3.1 | `false` |
| Spark 3.2 and later | `true` |

In Spark 3.2, the default was changed to `true` to make AQE a standard part of query execution.

**Sub-configurations**

When AQE is enabled, its individual features can be controlled separately. To enable or disable a specific AQE feature, set its sub-configuration. The master switch `spark.sql.adaptive.enabled` must be `true` for any sub-feature to take effect.

| Feature | Configuration | Default |
|---|---|---|
| Partition coalescing | `spark.sql.adaptive.coalescePartitions.enabled` | `true` |
| Skew join handling | `spark.sql.adaptive.skewJoin.enabled` | `true` |
| Local shuffle reader | `spark.sql.adaptive.localShuffleReader.enabled` | `true` |
| Join strategy conversion | Controlled by `spark.sql.adaptive.autoBroadcastJoinThreshold` | `10m` |

Example of enabling AQE and its sub-features:

```python
spark.conf.set("spark.sql.adaptive.enabled", "true")
spark.conf.set("spark.sql.adaptive.coalescePartitions.enabled", "true")
spark.conf.set("spark.sql.adaptive.skewJoin.enabled", "true")
spark.conf.set("spark.sql.adaptive.localShuffleReader.enabled", "true")
```

Example of disabling a specific AQE sub-feature while keeping AQE on:

```python
spark.conf.set("spark.sql.adaptive.enabled", "true")
spark.conf.set("spark.sql.adaptive.skewJoin.enabled", "false")
```

**Important interaction with Dynamic Partition Pruning (DPP)**

When AQE and Dynamic Partition Pruning (DPP) are enabled at the same time, DPP takes precedence over AQE during Spark SQL task execution. As a result, AQE does not take effect. Since DPP is enabled by default in many clusters, you must disable DPP to allow AQE to function.

To use AQE effectively:

```python
spark.conf.set("spark.sql.adaptive.enabled", "true")
spark.conf.set("spark.sql.optimizer.dynamicPartitionPruning.enabled", "false")
```

**When to disable AQE**

AQE is beneficial for most workloads, but there are cases where disabling it may be necessary:

- Driver out-of-memory errors during query planning. When a query is very complex with many joins, unions, or cached DataFrames, Spark regenerates the query plan text each time the plan changes. Extremely large plan strings can exceed memory limits and cause a driver `OutOfMemoryError`. In such cases, disabling AQE for that specific job can resolve the issue. As an alternative, you can limit the plan string length with `spark.sql.maxPlanStringLength` before disabling AQE entirely.

- Dynamic Partition Pruning conflict. If DPP is required and AQE is not taking effect, leaving AQE enabled adds no benefit. Disable AQE to avoid confusion.

- Debugging or comparing plans. When you need a stable, non-adaptive plan for debugging or benchmarking, disable AQE.

**Code example: full AQE configuration**

```python
from pyspark.sql import SparkSession

spark = (SparkSession.builder
         .appName("AQEConfigurationExample")
         .config("spark.sql.adaptive.enabled", "true")
         .config("spark.sql.adaptive.coalescePartitions.enabled", "true")
         .config("spark.sql.adaptive.advisoryPartitionSizeInBytes", "128m")
         .config("spark.sql.adaptive.skewJoin.enabled", "true")
         .config("spark.sql.adaptive.skewJoin.skewedPartitionFactor", "5")
         .config("spark.sql.adaptive.skewJoin.skewedPartitionThresholdInBytes", "256MB")
         .config("spark.sql.adaptive.localShuffleReader.enabled", "true")
         .config("spark.sql.adaptive.autoBroadcastJoinThreshold", "10m")
         .config("spark.sql.optimizer.dynamicPartitionPruning.enabled", "false")
         .getOrCreate())

df = spark.range(10000000).selectExpr("id as key", "id % 100 as group_id")
result = df.groupBy("group_id").count()
result.explain(True)
```

After execution, the physical plan will show `AdaptiveSparkPlan isFinalPlan=true` at the root, and the plan will include `AQEShuffleRead` nodes if partition coalescing occurred.

**Verifying the AQE setting**

You can check the current value of the configuration:

```python
print(spark.conf.get("spark.sql.adaptive.enabled"))
```

You can also check in the Spark UI SQL tab. If AQE is active, the physical plan will contain an `AdaptiveSparkPlan` node. If it is not, the plan will show the static physical plan without `AdaptiveSparkPlan`.

**Summary**

AQE is controlled by `spark.sql.adaptive.enabled`. It is enabled by default in Spark 3.2 and later. To disable it, set the property to `false`. When AQE and Dynamic Partition Pruning are both enabled, DPP takes precedence and AQE does not take effect, so DPP must be disabled for AQE to work. AQE's sub-features can be controlled independently while the master switch remains `true`. Disabling AQE may be necessary in cases of driver out-of-memory errors with very large query plans or when DPP conflict prevents AQE from functioning.
