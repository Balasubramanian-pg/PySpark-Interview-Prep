# 3.8.2 How do you create and access a Broadcast Variable in PySpark?

In PySpark, you create a broadcast variable using `sc.broadcast(value)` where `sc` is the SparkContext. The value can be any serializable Python object, such as a dictionary, list, tuple, set, or a small DataFrame collected to the driver. Once created, you access the broadcast value inside transformations and actions using the `.value` attribute. The broadcast variable is read-only and is distributed to all executors once, then cached for reuse by all tasks on that executor.

**Creating a broadcast variable**

```python
from pyspark.sql import SparkSession

spark = SparkSession.builder.appName("BroadcastExample").getOrCreate()
sc = spark.sparkContext

# The value to broadcast (any serializable Python object)
lookup = {"US": 1, "IN": 2, "UK": 3, "CA": 4}

# Create the broadcast variable
broadcast_lookup = sc.broadcast(lookup)
```

You can also broadcast a list, tuple, set, or a collected DataFrame:

```python
# Broadcast a list
codes = ["US", "IN", "UK", "CA"]
broadcast_codes = sc.broadcast(codes)

# Broadcast a DataFrame collected to the driver
small_df = spark.createDataFrame([("US", 1), ("IN", 2)], ["country", "id"])
small_list = small_df.collect()
broadcast_small = sc.broadcast(small_list)
```

**Accessing a broadcast variable**

Inside a transformation or action, access the broadcast value using `.value`. The value is deserialized and cached on the executor, so repeated access is fast.

Using it with RDDs:

```python
rdd = sc.parallelize(["US", "IN", "UK", "XX", "CA"])

# Access the broadcast dictionary inside a map transformation
result = rdd.map(lambda x: broadcast_lookup.value.get(x, 0)).collect()
print(result)  # [1, 2, 3, 0, 4]
```

Using it with DataFrames and UDFs:

```python
from pyspark.sql.functions import col, udf
from pyspark.sql.types import IntegerType

def map_country(code):
    return broadcast_lookup.value.get(code, 0)

map_udf = udf(map_country, IntegerType())

df = spark.createDataFrame([("US",), ("IN",), ("UK",), ("XX",)], ["country"])
result_df = df.withColumn("country_id", map_udf(col("country")))
result_df.show()
```

Using it inside `foreach` or `foreachPartition`:

```python
def process_row(row):
    value = broadcast_lookup.value.get(row, 0)
    # do something with value

rdd.foreach(process_row)
```

Using it inside a `mapPartitions` function:

```python
def process_partition(iterator):
    lookup = broadcast_lookup.value
    for item in iterator:
        yield lookup.get(item, 0)

result = rdd.mapPartitions(process_partition).collect()
```

**Unpersisting a broadcast variable**

Broadcast variables consume executor memory. When you no longer need the broadcast value, call `unpersist()` to release the cached data on all executors.

```python
broadcast_lookup.unpersist()
```

After calling `unpersist()`, the broadcast variable should not be used again. If you need the data, create a new broadcast variable.

**Complete example**

```python
from pyspark.sql import SparkSession
from pyspark.sql.functions import col, udf
from pyspark.sql.types import IntegerType

spark = SparkSession.builder.appName("BroadcastFullExample").getOrCreate()
sc = spark.sparkContext

# Value to broadcast
lookup = {"US": 1, "IN": 2, "UK": 3, "CA": 4}
broadcast_lookup = sc.broadcast(lookup)

# RDD usage
rdd = sc.parallelize(["US", "IN", "UK", "XX", "CA"])
rdd_result = rdd.map(lambda x: broadcast_lookup.value.get(x, 0)).collect()
print("RDD result:", rdd_result)

# DataFrame usage
def map_country(code):
    return broadcast_lookup.value.get(code, 0)

map_udf = udf(map_country, IntegerType())
df = spark.createDataFrame([("US",), ("IN",), ("UK",), ("XX",)], ["country"])
df_result = df.withColumn("country_id", map_udf(col("country")))
df_result.show()

# Release memory
broadcast_lookup.unpersist()

spark.stop()
```

**Accessing broadcast variables in the Spark UI**

The Spark UI does not show broadcast variable contents, but it shows memory usage under the Executors tab. Look at the "Storage Memory" column to see how much memory is used by broadcast blocks. If broadcast memory is high, unpersist variables that are no longer needed.

**Best practices**

- Broadcast only read-only data that is needed by all tasks.
- Ensure the broadcast value is small enough to fit in executor memory. A few hundred MB is usually safe, but this depends on your cluster.
- Unpersist broadcast variables when they are no longer needed.
- Do not modify the broadcast value. It is immutable.
- For DataFrame joins, prefer the `broadcast()` hint or `spark.sql.autoBroadcastJoinThreshold` instead of manually broadcasting a DataFrame.
- Use broadcast variables for lookup tables, dictionaries, and small configuration objects.
- Avoid broadcasting very large objects, as they can cause out-of-memory errors on executors.

**Common mistakes**

- Trying to broadcast a non-serializable object. PySpark uses Pickle to serialize broadcast values, so the object must be picklable.
- Accessing `.value` outside of a task, such as on the driver after broadcasting. This works but does not provide the caching benefit; the value is already on the driver.
- Forgetting to unpersist broadcast variables, leading to memory leaks in long-running applications.
- Broadcasting a value that is too large, causing executor out-of-memory errors.
- Modifying the broadcast value after creation. It is read-only.

**Summary**

To create a broadcast variable in PySpark, use `sc.broadcast(value)`. To access it, use `.value` inside transformations and actions. Broadcast variables distribute read-only data to all executors once and cache it, reducing network IO and serialization overhead. Always unpersist when no longer needed. Use them for lookup tables, dictionaries, and small configuration objects. Avoid broadcasting large objects that do not fit in executor memory.
