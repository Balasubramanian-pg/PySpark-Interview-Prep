# 3.8.3 What are Accumulators and what are they typically used for?

An accumulator is a write-only shared variable that allows executors to add values to a shared counter or sum. The driver can read the accumulator's value only after an action completes. Accumulators are used for aggregating information from executors back to the driver, such as counting events, summing values, or tracking errors during a distributed computation. They are part of Spark's shared variables along with broadcast variables.

**How accumulators work**

- The driver creates an accumulator with an initial value, such as `sc.accumulator(0)`.
- Executors can only add to the accumulator using the `add()` method. They cannot read its value.
- Accumulator updates are sent back to the driver as tasks complete.
- After an action finishes, the driver can read the final value using `.value`.
- By default, accumulators support numeric types (int, float, long). You can create custom accumulators by subclassing `AccumulatorParam`.

**Typical uses of accumulators**

1. Counting events: Count the number of malformed records, null values, or rows that meet a condition.
2. Summing values: Compute the total of some metric across all tasks, such as total bytes processed or total sales amount.
3. Debugging and monitoring: Track how many times a particular branch of code is executed, or count errors and warnings.
4. Data quality checks: Count invalid rows, missing values, or out-of-range values during ETL pipelines.
5. Performance metrics: Count the number of records processed per partition or the number of retries.

**Creating and using an accumulator in PySpark**

```python
from pyspark.sql import SparkSession

spark = SparkSession.builder.appName("AccumulatorExample").getOrCreate()
sc = spark.sparkContext

# Create an accumulator with initial value 0
invalid_count = sc.accumulator(0)

# Sample data with some invalid rows
data = [1, 2, -3, 4, -5, 6, -7]

def validate_row(value):
    global invalid_count
    if value < 0:
        invalid_count.add(1)
    return value

rdd = sc.parallelize(data)

# Use accumulator inside an action (foreach)
rdd.foreach(validate_row)

# Read the final value on the driver
print("Number of invalid rows:", invalid_count.value)  # 3

spark.stop()
```

**Using accumulators with DataFrames**

You can use accumulators inside `foreach` or `foreachPartition` on a DataFrame.

```python
from pyspark.sql import SparkSession

spark = SparkSession.builder.appName("AccumulatorDF").getOrCreate()
sc = spark.sparkContext

error_count = sc.accumulator(0)

df = spark.createDataFrame([(1, "a"), (2, "b"), (-3, "c"), (4, "d")], ["id", "name"])

def check_row(row):
    global error_count
    if row["id"] < 0:
        error_count.add(1)

df.foreach(check_row)

print("Negative IDs:", error_count.value)  # 1

spark.stop()
```

**Custom accumulators**

You can create accumulators for non-numeric types by subclassing `AccumulatorParam`.

```python
from pyspark import AccumulatorParam

class SetAccumulatorParam(AccumulatorParam):
    def zero(self, initial_value):
        return set()
    def addInPlace(self, v1, v2):
        v1.update(v2)
        return v1

sc = spark.sparkContext
seen_codes = sc.accumulator(set(), SetAccumulatorParam())

def track_code(code):
    global seen_codes
    seen_codes.add({code})

rdd = sc.parallelize(["US", "IN", "US", "UK"])
rdd.foreach(track_code)

print("Distinct codes seen:", seen_codes.value)  # {'US', 'IN', 'UK'}
```

**Important pitfalls**

Accumulators should only be used inside actions, not inside transformations. Transformations are lazy and can be recomputed if a task fails or if the RDD is recomputed. If an accumulator is updated inside a transformation, the update may happen multiple times, leading to incorrect results.

Incorrect usage inside a transformation:

```python
acc = sc.accumulator(0)
rdd = sc.parallelize([1, 2, 3, 4])
rdd.map(lambda x: acc.add(x))  # lazy, not executed yet
rdd.count()  # action triggers computation
print(acc.value)  # may be incorrect if tasks are recomputed
```

Correct usage inside an action:

```python
acc = sc.accumulator(0)
rdd = sc.parallelize([1, 2, 3, 4])
rdd.foreach(lambda x: acc.add(x))  # action
print(acc.value)  # 10
```

In Spark 2.x and later, accumulators used in transformations may only be updated once per task if the task is not recomputed. However, if a task fails and is retried, the accumulator update may be applied again, causing double counting. The safest approach is to use accumulators only in actions.

Accumulators are not fault-tolerant in the sense that updates may be re-applied on task retry. For exact counts, use actions that do not recompute, such as `foreach` on a cached dataset, or use a DataFrame aggregation instead.

**Differences from broadcast variables**

| Aspect | Broadcast Variables | Accumulators |
|---|---|---|
| Direction | Driver to executors | Executors to driver |
| Read/Write | Read-only | Write-only (add-only) |
| Purpose | Distribute large read-only data efficiently | Aggregate counters or sums from executors |
| Usage | Inside transformations and actions | Inside actions (preferably) |
| Serialization | Sent once per executor, cached | Updates sent back to driver |
| Fault tolerance | Immutable, can be re-broadcast | Updates may be re-applied on task retry |
| Memory location | Executor memory | Driver memory (for the final value) |

**Best practices**

- Use accumulators only inside actions, not transformations.
- Do not rely on accumulators for exact counts if tasks may be recomputed. For exact counts, use DataFrame aggregations or RDD actions on cached data.
- Use named accumulators for easier identification in the Spark UI.
- For custom types, subclass `AccumulatorParam`.
- Accumulators are only visible to the driver after an action completes. Do not try to read `.value` inside an executor.
- Monitor accumulator values in the Spark UI under the Stages tab for debugging.

**Summary**

Accumulators are write-only shared variables that allow executors to add values to a shared counter or sum. The driver reads the final value after an action completes. They are typically used for counting events, summing metrics, debugging, and data quality checks. Use them only inside actions to avoid incorrect results from recomputation. Accumulators are not fault-tolerant for exact counts, so use DataFrame aggregations when exact results are required. They complement broadcast variables, which handle driver-to-executor distribution, while accumulators handle executor-to-driver aggregation.
