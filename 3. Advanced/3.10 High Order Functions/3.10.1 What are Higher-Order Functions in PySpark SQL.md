# 3.10.1 What are Higher-Order Functions in PySpark SQL?

### 3.10.1 What are Higher-Order Functions in PySpark SQL

Higher-order functions in PySpark SQL are built-in functions that accept one or more lambda functions as arguments. They operate directly on complex data types such as arrays and maps. Instead of exploding an array into multiple rows, applying a transformation, and then grouping back, you can express the entire operation in a single expression. They are part of the Spark SQL function library and are optimized by the Catalyst optimizer and Tungsten. They avoid the serialization overhead of Python UDFs and the shuffle cost of explode-and-collect operations.

**Why higher-order functions are useful**

- Performance: They are implemented natively in Spark and benefit from whole-stage code generation. They do not cross the JVM-Python boundary like UDFs.
- Conciseness: A single expression replaces multiple explode, groupBy, and collect_list steps.
- Readability: The intent to transform or filter an array is clear.
- No data explosion: You do not create intermediate rows, which reduces shuffle, memory, and disk I/O.
- Catalyst optimization: Predicate pushdown, column pruning, and other optimizations can still apply because the function is part of the query plan.

**Common higher-order functions**

- `transform(array, lambda)`: applies a lambda to each element and returns a new array.
- `filter(array, lambda)`: returns a new array with elements that satisfy the predicate.
- `exists(array, lambda)`: returns true if any element satisfies the predicate.
- `forall(array, lambda)`: returns true if all elements satisfy the predicate.
- `aggregate(array, initial, merge, finish)`: reduces an array to a single value.
- `zip_with(array1, array2, lambda)`: combines two arrays element-wise.
- `transform_values(map, lambda)`: applies a lambda to each value in a map.
- `transform_keys(map, lambda)`: applies a lambda to each key in a map.
- `map_filter(map, lambda)`: filters map entries based on a predicate.
- `map_zip_with(map1, map2, lambda)`: combines two maps by key.

**Syntax in PySpark**

In PySpark, lambdas are written with the `lambda` keyword. The lambda receives the element or key-value pair as arguments.

```python
from pyspark.sql.functions import transform, filter, exists, forall, aggregate, zip_with, col, lit
```

**Example: transform**

`transform` applies a lambda to each element of an array and returns a new array of the same length.

```python
df = spark.createDataFrame([(1, [1, 2, 3]), (2, [4, 5, 6])], ["id", "numbers"])
df.select("id", transform(col("numbers"), lambda x: x * 2).alias("doubled")).show()
```

Output:
```
+---+---------+
| id|  doubled|
+---+---------+
|  1|[2, 4, 6]|
|  2|[8,10,12]|
+---+---------+
```

You can also use the index in the lambda:

```python
df.select("id", transform(col("numbers"), lambda x, i: x + i).alias("indexed")).show()
```

**Example: filter**

`filter` returns a new array containing only the elements that satisfy the predicate.

```python
df.select("id", filter(col("numbers"), lambda x: x % 2 == 0).alias("evens")).show()
```

Output:
```
+---+------+
| id| evens|
+---+------+
|  1|   [2]|
|  2|[4, 6]|
+---+------+
```

**Example: exists and forall**

`exists` returns true if at least one element satisfies the predicate. `forall` returns true if all elements satisfy the predicate.

```python
df.select(
    "id",
    exists(col("numbers"), lambda x: x > 2).alias("any_gt_2"),
    forall(col("numbers"), lambda x: x > 0).alias("all_positive")
).show()
```

Output:
```
+---+---------+------------+
| id|any_gt_2 |all_positive|
+---+---------+------------+
|  1|     true|        true|
|  2|     true|        true|
+---+---------+------------+
```

**Example: aggregate**

`aggregate` reduces an array to a single value. It takes an initial value, a merge function, and an optional finish function.

```python
df.select("id", aggregate(col("numbers"), lit(0), lambda acc, x: acc + x).alias("sum")).show()
```

Output:
```
+---+---+
| id|sum|
+---+---+
|  1|  6|
|  2| 15|
+---+---+
```

With a finish function to compute an average:

```python
df.select(
    "id",
    aggregate(
        col("numbers"),
        (lit(0), lit(0)),
        lambda acc, x: (acc[0] + x, acc[1] + 1),
        lambda acc: acc[0] / acc[1]
    ).alias("average")
).show()
```

**Example: zip_with**

`zip_with` combines two arrays element-wise using a lambda. The arrays must have the same length.

```python
df2 = spark.createDataFrame([
    (1, [1, 2, 3], [10, 20, 30]),
    (2, [4, 5, 6], [40, 50, 60])
], ["id", "a", "b"])

df2.select("id", zip_with(col("a"), col("b"), lambda x, y: x + y).alias("summed")).show()
```

Output:
```
+---+-----------+
| id|     summed|
+---+-----------+
|  1|[11, 22, 33]|
|  2|[44, 55, 66]|
+---+-----------+
```

**Example: higher-order functions on maps**

Spark provides `transform_values`, `transform_keys`, `map_filter`, and `map_zip_with` for maps.

```python
from pyspark.sql.functions import transform_values, map_filter

df3 = spark.createDataFrame([
    (1, {"a": 1, "b": 2}),
    (2, {"c": 3, "d": 4})
], ["id", "map_col"])

df3.select("id", transform_values(col("map_col"), lambda k, v: v * 10).alias("new_map")).show()
df3.select("id", map_filter(col("map_col"), lambda k, v: v > 1).alias("filtered")).show()
```

**Comparison with explode and UDFs**

Explode approach: explodes the array into rows, transforms each row, then groups back with collect_list. This causes a shuffle and increases data size.

```python
from pyspark.sql.functions import explode, collect_list

df.select("id", explode("numbers").alias("num")) \
  .withColumn("num", col("num") * 2) \
  .groupBy("id").agg(collect_list("num").alias("doubled")) \
  .show()
```

UDF approach: requires serialization between JVM and Python, does not benefit from Catalyst optimization, and is slower for large datasets.

```python
from pyspark.sql.functions import udf
from pyspark.sql.types import ArrayType, IntegerType

def double_array(arr):
    return [x * 2 for x in arr] if arr else None

double_udf = udf(double_array, ArrayType(IntegerType()))
df.select("id", double_udf(col("numbers")).alias("doubled")).show()
```

Higher-order function approach: single expression, no shuffle, native implementation.

```python
df.select("id", transform(col("numbers"), lambda x: x * 2).alias("doubled")).show()
```

**Syntax in Spark SQL**

In SQL, lambdas are written with the arrow syntax `x -> ...` or `(x, i) -> ...`.

```sql
SELECT id, transform(numbers, x -> x * 2) AS doubled FROM my_table;
SELECT id, filter(numbers, x -> x % 2 = 0) AS evens FROM my_table;
SELECT id, aggregate(numbers, 0, (acc, x) -> acc + x) AS total FROM my_table;
```

**Common pitfalls and limitations**

- Null handling: If the array is null, the result is null. If an element is null, the lambda may need to handle it. Use `coalesce` or check for null.
- Array length for `zip_with`: Both arrays must have the same length. If they differ, the result is null.
- Type inference: The return type of the lambda must be compatible with Spark's type system. In some cases, you may need to cast the result.
- Memory: Higher-order functions operate on arrays that must fit in memory. Very large arrays can cause memory pressure.
- Nested arrays: Deeply nested expressions can become hard to read. Consider breaking them into steps.
- Python lambda limitations: In PySpark, lambdas cannot be too complex. For very complex logic, a UDF may still be necessary, but this should be rare.

**Summary**

Higher-order functions in PySpark SQL are built-in functions that accept lambda expressions and operate on arrays and maps. They allow you to transform, filter, and aggregate nested data in a single expression without exploding the data or using Python UDFs. They are faster, more concise, and benefit from Catalyst optimization. Common functions include `transform`, `filter`, `exists`, `forall`, `aggregate`, `zip_with`, `transform_values`, `transform_keys`, `map_filter`, and `map_zip_with`. Use them whenever you need to process nested data, and prefer them over explode-and-collect or UDFs.
