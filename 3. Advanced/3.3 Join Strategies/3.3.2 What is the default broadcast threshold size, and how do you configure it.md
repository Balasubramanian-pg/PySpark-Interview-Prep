# 3.3.2 What is the default broadcast threshold size, and how do you configure it?
The default broadcast threshold in Spark is **10 MB** (exactly 10,485,760 bytes). This is controlled by the configuration property `spark.sql.autoBroadcastJoinThreshold`, which sets the maximum table size in bytes that can be automatically broadcast to all worker nodes during a join operation. Setting this value to `-1` disables automatic broadcasting entirely.

### How to Configure the Broadcast Threshold

You can configure this threshold in several ways, depending on your workflow.

**At SparkSession creation (PySpark):**

```python
from pyspark.sql import SparkSession

spark = (SparkSession.builder
         .appName("MyApp")
         .config("spark.sql.autoBroadcastJoinThreshold", "20971520")  # 20 MB
         .getOrCreate())
```

**At runtime (PySpark):**

```python
spark.conf.set("spark.sql.autoBroadcastJoinThreshold", "20971520")  # 20 MB
```

**At runtime (Scala):**

```scala
spark.conf.set("spark.sql.autoBroadcastJoinThreshold", 20 * 1024 * 1024)  // 20 MB
```

**Using SQL:**

```sql
SET spark.sql.autoBroadcastJoinThreshold=20971520;
```

**Using spark-submit:**

```bash
spark-submit --conf spark.sql.autoBroadcastJoinThreshold=20971520 my_app.py
```

**In spark-defaults.conf:**

```properties
spark.sql.autoBroadcastJoinThreshold=20971520
```

### Important Considerations

**When to increase the threshold:** If your dimension tables are larger than 10 MB but still fit comfortably in executor memory, increasing the threshold allows Spark to automatically choose broadcast joins for more cases. This avoids shuffling large fact tables, which is the most expensive part of a join.

**When to decrease or disable the threshold:** Setting it to `-1` disables automatic broadcasting. This is useful when you want to force sort-merge joins, or when broadcast joins are causing out-of-memory errors on executors. You can also set it to a very small value to effectively disable automatic broadcasting while still allowing manual hints.

**Adaptive Query Execution (AQE) and broadcasting:** In Spark 3.x, AQE has its own broadcast threshold configuration: `spark.sql.adaptive.autoBroadcastJoinThreshold`. Its default value is the same as `spark.sql.autoBroadcastJoinThreshold`. AQE can convert a sort-merge join to a broadcast hash join at runtime if one side turns out to be small enough after filtering, using this threshold. This means even if you don't increase the static threshold, AQE may still choose a broadcast join when appropriate.

**Manual broadcast hints:** You can override the threshold on a per-join basis using the `broadcast()` hint in the DataFrame API or `/*+ BROADCAST(table) */` in SQL. This is useful when you know a table is small but Spark's statistics are inaccurate.

```python
from pyspark.sql.functions import broadcast
result = large_df.join(broadcast(small_df), "customer_id")
```

**Memory safety:** Broadcasting a table that is too large can cause `OutOfMemoryError` on the driver and executors. The broadcast table must fit in the memory of each executor. Before raising the threshold significantly, verify that your executors have sufficient memory and that the dimension tables are actually small enough to broadcast safely.
