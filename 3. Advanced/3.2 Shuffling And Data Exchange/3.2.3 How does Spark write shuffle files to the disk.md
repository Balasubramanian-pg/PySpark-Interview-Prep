# 3.2.3 How does Spark write shuffle files to the disk?

### 3.2.3 How does Spark write shuffle files to the disk?

Spark's shuffle write process is designed to efficiently manage large volumes of data that cannot fit in memory. Since Spark 2.0, the default and only shuffle manager is `SortShuffleManager`, which writes data to local disk in a structured way to minimize the number of files and enable fast fetches by downstream tasks.

The process operates in three main phases: buffering data in memory, spilling to disk when memory is full, and merging temporary files into a final data file and index file.

**Phase 1: In-memory buffering and pre-aggregation**

When a shuffle map task starts, it processes records from its input partition. Each record is assigned to a target reduce partition based on the shuffle key. For aggregation operations like `reduceByKey`, Spark uses a `Map` data structure to perform map-side pre-aggregation, combining values for the same key before writing them anywhere. For non-aggregation operations like a simple `join`, an `Array` is used to store records directly.

These records are held in an in-memory buffer. Spark monitors the size of this buffer and triggers a spill to disk when it exceeds a configurable memory threshold.

**Phase 2: Spilling to disk**

When the in-memory buffer is full, Spark sorts the buffered records by `partitionId` and, if required, by key. The sorted data is then written to a temporary spill file on local disk. Each spill creates a new temporary file, and the process resets the in-memory buffer for the next batch of records.

Writing to disk is not done byte-by-byte. Spark uses a buffered output stream to reduce the number of disk seeks and system calls. The buffer size is controlled by the configuration `spark.shuffle.file.buffer`, which defaults to 32 KB. Records are accumulated in this buffer and flushed to the disk file in larger chunks, improving I/O efficiency.

**Phase 3: Merging spill files and generating the final output**

After the map task has processed all its input records, it may have produced several temporary spill files plus some remaining data in memory. Spark then performs a merge operation to combine all of these into a single final data file and a corresponding index file.

The merge step reads the spill files and the in-memory data, writing the final output in order of partition ID. The resulting **data file** contains all the shuffle data for this map task, with records for each reduce partition stored contiguously. A separate **index file** is created that records the start and end offset of each partition's block within the data file. This index allows reduce tasks to efficiently locate and fetch only the data they need, without reading the entire file.

**Different ShuffleWriter implementations**

`SortShuffleManager` selects one of three shuffle writers based on the operation and configuration:

- **`SortShuffleWriter`**: The default writer for most operations. It performs the full sort and spill process described above.
- **`UnsafeShuffleWriter`**: Used for operations that do not require sorted output and when data is in a binary format (e.g., Tungsten-based DataFrames). It skips the sorting step and operates directly on serialized binary data, reducing CPU and memory overhead.
- **`BypassMergeSortShuffleWriter`**: Activated when the number of reduce partitions is below the threshold set by `spark.shuffle.sort.bypassMergeThreshold` (default 200) and the operation is not an aggregation. It writes data directly to separate files per partition (like the old hash-based shuffle) and then merges them into one file with an index, avoiding the in-memory sort.

**Key configuration parameters**

- `spark.shuffle.file.buffer`: Size of the in-memory buffer for each shuffle file output stream. Default 32 KB. Increasing it can reduce disk I/O at the cost of more memory.
- `spark.shuffle.spill.diskWriteBufferSize`: Buffer size for writing sorted records to the spill file. Default 1 MB.
- `spark.shuffle.sort.bypassMergeThreshold`: Number of reduce partitions below which the bypass mechanism is used. Default 200.
- `spark.shuffle.compress`: Whether to compress shuffle output. Default true.

**Summary**

Spark writes shuffle data to disk by buffering records in memory, spilling sorted batches to temporary files when memory fills, and finally merging those files into a single data file with an index that records partition offsets. This design reduces the number of files from the old `M × N` scheme to just one data file and one index file per map task, while still allowing reducers to fetch only the data they need.
