### 3.9.3 Explain the difference between Series-to-Series and Iterator-to-Iterator Pandas UDFs

Pandas UDFs can be categorized by their input and output types. The two most common types for scalar transformations are Series-to-Series and Iterator-to-Iterator (formally, Iterator of Series to Iterator of Series). Both process data in batches using Apache Arrow and pandas, but they differ in how the function is invoked, what inputs it can accept, and when initialization happens. Understanding these differences helps you choose the right type for your use case.

**Series-to-Series Pandas UDF**

A Series-to-Series Pandas UDF takes one or more pandas Series as input and returns a pandas Series of the same length. It is the simplest and most common type. The function is called once per Arrow batch, and the entire batch is passed as pandas Series. It can accept multiple input columns by declaring multiple Series parameters.

Type hint: `pandas.Series -> pandas.Series` or `Tuple[pandas.Series, ...] -> pandas.Series`.

When to use:
- When you have a simple vectorized operation that applies to each batch independently.
- When you need to operate on multiple input columns.
- When no expensive initialization is required, or initialization can be done inside the function on each batch (which may be wasteful).

Example: multiply two columns.

```python
import pandas as pd
from pyspark.sql.functions import pandas_udf
from pyspark.sql.types import LongType

@pandas_udf(LongType())
def multiply(a: pd.Series, b: pd.Series) -> pd.Series:
    return a * b

df = spark.createDataFrame([(1, 2), (3, 4), (5, 6)], ["a", "b"])
df.select(multiply(df["a"], df["b"])).show()
```

In the physical plan, this appears as `ArrowEvalPython`. The function is called once per batch, and the input is a pair of pandas Series representing the entire batch for columns `a` and `b`.

**Iterator-to-Iterator Pandas UDF**

An Iterator-to-Iterator Pandas UDF takes an iterator of pandas Series as input and returns an iterator of pandas Series as output. The function is called once per Arrow batch, but instead of receiving the batch directly, it receives an iterator that yields batches one at a time. The function can iterate over the input batches and yield output batches. This design allows you to perform expensive initialization once per function call, before processing any batches.

Type hint: `Iterator[pandas.Series] -> Iterator[pandas.Series]` or `Iterator[Tuple[pandas.Series, ...]] -> Iterator[pandas.Series]` for multiple columns.

Important limitation: The basic Iterator of Series to Iterator of Series UDF can only take a single Spark column as input. To process multiple columns with iterator-based logic, you must use the Iterator of Multiple Series to Iterator of Series variant, which takes an iterator of tuples of pandas Series.

When to use:
- When you need to initialize some state once per function call, such as loading a machine learning model file.
- When the initialization is expensive and should not be repeated for every batch.
- When you need to process multiple batches in a streaming fashion within a single function call.
- When you want to avoid the overhead of re-initializing per batch.

Example: load a model once and apply it to all batches.

```python
import pandas as pd
from typing import Iterator
from pyspark.sql.functions import pandas_udf

@pandas_udf("double")
def predict(iterator: Iterator[pd.Series]) -> Iterator[pd.Series]:
    # Load model once per function call
    model = load_model()
    for s in iterator:
        # Apply model to each batch
        yield model.predict(s)
```

The key difference is that the `load_model()` call happens once per Python worker function invocation, not once per batch. In a Series-to-Series UDF, if you loaded the model inside the function, it would be reloaded for every batch, which is inefficient.

**Key Differences**

| Aspect | Series-to-Series | Iterator-to-Iterator |
|---|---|---|
| Input type | One or more pandas Series | Iterator of pandas Series (or tuples of Series for multiple columns) |
| Output type | pandas Series | Iterator of pandas Series |
| Function call | Once per batch, receives batch directly | Once per function invocation, receives iterator of batches |
| Initialization | Must be done inside the function per batch | Can be done once before iterating over batches |
| Multiple input columns | Supported directly | Supported only with Iterator of Multiple Series to Iterator of Series |
| Use case | Simple vectorized operations | Expensive initialization (e.g., model loading) |
| Physical plan node | `ArrowEvalPython` | `ArrowEvalPython` or `MapInPandas` (depending on usage) |
| Performance | Good for simple operations | Better when initialization cost is high |

**When to use which**

Use Series-to-Series when:
- Your operation is a pure vectorized transformation that does not require expensive setup.
- You need to operate on multiple columns simultaneously.
- The overhead of re-initializing per batch is negligible.
- You are doing simple arithmetic, string manipulation, or date operations.

Use Iterator-to-Iterator when:
- You need to load a large model or resource once per function call.
- The initialization cost is significant and would dominate if repeated per batch.
- You need to process multiple input columns with iterator-based logic (using Iterator of Multiple Series to Iterator of Series).
- You want to stream through batches and potentially maintain state across batches.

**Limitations of Iterator-to-Iterator**

- The basic Iterator of Series to Iterator of Series UDF can only take a single Spark column as input. For multiple columns, use Iterator of Multiple Series to Iterator of Series.
- The length of the entire output must match the length of the entire input. You cannot change the number of rows.
- The function must be a generator or return an iterator. If it returns a list, it will be treated as a single batch.
- The initialization happens once per Python worker function invocation, not once per partition. If the Python worker is reused across multiple partitions, initialization may happen multiple times.

**Code example comparing both**

Series-to-Series:

```python
@pandas_udf("double")
def add_one_series(s: pd.Series) -> pd.Series:
    return s + 1
```

Iterator-to-Iterator:

```python
@pandas_udf("double")
def add_one_iterator(iterator: Iterator[pd.Series]) -> Iterator[pd.Series]:
    for s in iterator:
        yield s + 1
```

The Iterator version allows you to add initialization code before the loop:

```python
@pandas_udf("double")
def add_one_with_init(iterator: Iterator[pd.Series]) -> Iterator[pd.Series]:
    # Expensive initialization once per function call
    offset = compute_expensive_offset()
    for s in iterator:
        yield s + offset
```

**Summary**

Series-to-Series Pandas UDFs take pandas Series as input and return a pandas Series, calling the function once per batch. They are simple and support multiple input columns directly. Iterator-to-Iterator Pandas UDFs take an iterator of pandas Series and return an iterator of pandas Series, allowing expensive initialization to be performed once per function call rather than once per batch. The basic iterator version supports only a single input column, while the multiple-series variant supports multiple columns. Use Series-to-Series for simple vectorized transformations and Iterator-to-Iterator when initialization cost is high or when you need to stream through batches with state. Both use Arrow for efficient data transfer and are much faster than scalar Python UDFs.
