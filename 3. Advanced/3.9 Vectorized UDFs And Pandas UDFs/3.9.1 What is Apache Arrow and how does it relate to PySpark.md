# 3.9.1 What is Apache Arrow and how does it relate to PySpark?

Apache Arrow is an in-memory columnar data format that is used in Spark to efficiently transfer data between JVM and Python processes. It is a cross-language development platform for in-memory data that specifies a standardized columnar memory format, allowing different systems to share data without serialization and deserialization overhead. Its usage is most beneficial to Python users who work with Pandas and NumPy data. PyArrow is the Python binding for Apache Arrow.

**The Problem Arrow Solves**

In PySpark, the driver runs on the JVM, while Python code (such as UDFs and Pandas conversions) runs in separate Python worker processes. Without Arrow, data must be serialized row by row using pickle or cloudpickle, sent from the JVM to a Python worker process, deserialized, processed, serialized again, and sent back to the JVM. This per-row serialization and deserialization is the primary performance bottleneck for Python UDFs and Pandas DataFrame conversions.

Apache Arrow eliminates this bottleneck by providing a columnar in-memory format that both the JVM and Python can understand natively. Data is transferred in batches without expensive per-row pickling, and the columnar layout is optimized for vectorized operations.

**How Arrow Relates to PySpark**

Arrow is used in PySpark in several key areas:

1. **Pandas UDFs (Vectorized UDFs)**

Pandas UDFs are user-defined functions that are executed by Spark using Arrow to transfer data and Pandas to work with the data, allowing vectorized operations. Instead of processing one row at a time, Spark splits the data into batches of rows, calls the Python function for each batch, and concatenates the results. Arrow handles the data transfer between the JVM and Python, and Pandas provides the vectorized operations on Series and DataFrames. No additional configuration is required for Pandas UDFs to use Arrow.

2. **Conversion between PySpark DataFrames and Pandas DataFrames**

Arrow is available as an optimization when converting a Spark DataFrame to a Pandas DataFrame using `toPandas()` and when creating a Spark DataFrame from a Pandas DataFrame using `createDataFrame(pandas_df)`. To use Arrow for these methods, set the Spark configuration `spark.sql.execution.arrow.pyspark.enabled` to `true`. In Spark 4.x, this configuration is enabled by default.

3. **Arrow UDFs (Newer Alternative)**

A newer advancement is native Arrow UDFs, which operate directly on Arrow data without converting to Pandas or NumPy. This eliminates the Pandas/Arrow conversion overhead entirely. Benchmarks show Arrow UDFs are approximately 10% faster and use about 40% less memory than Pandas UDFs, with better support for complex data types.

4. **Conversion to/from Arrow Table (Spark 4.0+)**

From Spark 4.0, you can create a Spark DataFrame from a PyArrow Table with `SparkSession.createDataFrame()`, and you can convert a Spark DataFrame to a PyArrow Table with `DataFrame.toArrow()`.

**Enabling Arrow in PySpark**

For Pandas UDFs, Arrow is used automatically. For `toPandas()` and `createDataFrame()`, the configuration must be enabled:

```python
spark.conf.set("spark.sql.execution.arrow.pyspark.enabled", "true")
```

To install PyArrow, use the command `pip install pyspark[sql]` if you installed PySpark using pip. Otherwise, ensure PyArrow is installed and available on all cluster nodes.

**Example: Conversion between PySpark and Pandas DataFrames**

```python
import numpy as np
import pandas as pd

# Enable Arrow-based columnar data transfers
spark.conf.set("spark.sql.execution.arrow.pyspark.enabled", "true")

# Generate a Pandas DataFrame
pdf = pd.DataFrame(np.random.rand(100, 3))

# Create a Spark DataFrame from a Pandas DataFrame using Arrow
df = spark.createDataFrame(pdf)

# Convert the Spark DataFrame back to a Pandas DataFrame using Arrow
result_pdf = df.select("*").toPandas()
```

Using the above optimizations with Arrow will produce the same results as when Arrow is not enabled.

**Example: Pandas UDF**

```python
import pandas as pd
from pyspark.sql.functions import pandas_udf
from pyspark.sql.types import LongType

@pandas_udf(LongType())
def multiply(a: pd.Series, b: pd.Series) -> pd.Series:
    return a * b

df = spark.createDataFrame([(1, 2), (3, 4), (5, 6)], ["a", "b"])
df.select(multiply(df["a"], df["b"])).show()
```

**Performance Benefits**

The primary benefit of Arrow is the reduction in serialization and deserialization overhead. Arrow's columnar format allows data to be transferred between the JVM and Python in batches without the expensive per-row pickling. Vectorized operations then apply a single function call to an entire column rather than iterating over each row. The performance difference is substantial. Benchmarks show vectorized Python UDFs can be up to 5.76x faster than scalar Python UDFs, and in some workloads the improvement can reach 100x.

**Limitations and Considerations**

- **Supported data types.** Not all Spark and Arrow data types are currently supported. An error can be raised if a column has an unsupported type. For example, `BinaryType`, `MapType`, `ArrayType` of `TimestampType`, and nested `StructType` are not supported for Arrow-based conversion in some versions.

- **Collection to driver.** Even with Arrow, `toPandas()` and `toArrow()` result in the collection of all records in the DataFrame to the driver program and should be done on a small subset of the data.

- **Fallback behavior.** Optimizations enabled by `spark.sql.execution.arrow.pyspark.enabled` can fall back automatically to a non-Arrow implementation if an error occurs before the actual computation within Spark. This can be controlled by `spark.sql.execution.arrow.pyspark.fallback.enabled`.

- **Batch size.** The batch size for Arrow transfers is controlled by `spark.sql.execution.arrow.maxRecordsPerBatch` (default 10,000). For wide DataFrames or large rows, reduce this value to avoid out-of-memory errors on the Python worker. For narrow DataFrames, increase it to reduce per-batch overhead.

- **Zero-copy caveats.** Arrow enables zero-copy conversion in some cases, but columns with NULL values trigger deep copies. The "zero-copy" promise of Arrow in a PySpark context has hidden overhead that depends on the data.

**Summary**

Apache Arrow is an in-memory columnar data format that Spark uses to efficiently transfer data between the JVM and Python processes. It is the foundation for Pandas UDFs and enables fast conversion between PySpark DataFrames and Pandas DataFrames. Arrow eliminates the per-row serialization bottleneck that makes scalar Python UDFs slow, allowing vectorized operations on batches of data. PyArrow is the Python binding for Arrow and must be installed on all cluster nodes. Enable `spark.sql.execution.arrow.pyspark.enabled` to use Arrow for `toPandas()` and `createDataFrame()`. Pandas UDFs use Arrow automatically. For maximum performance, consider native Arrow UDFs which eliminate the Pandas conversion overhead entirely. Be aware of supported data types, fallback behavior, and batch size configuration.
