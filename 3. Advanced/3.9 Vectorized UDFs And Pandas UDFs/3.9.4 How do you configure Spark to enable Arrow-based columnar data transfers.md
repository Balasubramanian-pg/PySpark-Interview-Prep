# 3.9.4 How do you configure Spark to enable Arrow-based columnar data transfers?

To enable Arrow-based columnar data transfers in Spark, you set the configuration property `spark.sql.execution.arrow.pyspark.enabled` to `true`. This optimization is used when converting a PySpark DataFrame to a pandas DataFrame with `toPandas()` and when creating a PySpark DataFrame from a pandas DataFrame with `createDataFrame(pandas_df)`.

### Configuration Property

| Property | Default | Description |
|---|---|---|
| `spark.sql.execution.arrow.pyspark.enabled` | `false` (Spark 3.x) / `true` (Spark 4.2+) | Enables Arrow-based columnar data transfer between JVM and Python |
| `spark.sql.execution.arrow.pyspark.fallback.enabled` | `true` | Controls whether Spark falls back to a non-Arrow implementation if an error occurs during Arrow-based conversion |

In Spark 4.2, the default for `spark.sql.execution.arrow.pyspark.enabled` changed to `true`, and columnar data exchange between PySpark and the JVM uses Apache Arrow by default. To restore the legacy non-Arrow row-based exchange, set it to `false`.

### How to Set the Configuration

At SparkSession creation (PySpark):

```python
from pyspark.sql import SparkSession

spark = (SparkSession.builder
         .appName("ArrowExample")
         .config("spark.sql.execution.arrow.pyspark.enabled", "true")
         .getOrCreate())
```

At runtime (PySpark):

```python
spark.conf.set("spark.sql.execution.arrow.pyspark.enabled", "true")
```

Using SQL:

```sql
SET spark.sql.execution.arrow.pyspark.enabled=true;
```

Using spark-submit:

```bash
spark-submit --conf spark.sql.execution.arrow.pyspark.enabled=true my_app.py
```

Using spark-defaults.conf:

```properties
spark.sql.execution.arrow.pyspark.enabled=true
```

### Prerequisite: Install PyArrow

Before enabling Arrow, ensure PyArrow is installed on all cluster nodes. If you install PySpark using pip, you can bring in PyArrow as an extra dependency:

```bash
pip install pyspark[sql]
```

Otherwise, install PyArrow using pip or conda from the conda-forge channel.

### Code Example

```python
import numpy as np
import pandas as pd

# Enable Arrow-based columnar data transfers
spark.conf.set("spark.sql.execution.arrow.pyspark.enabled", "true")

# Generate a pandas DataFrame
pdf = pd.DataFrame(np.random.rand(100, 3))

# Create a Spark DataFrame from a pandas DataFrame using Arrow
df = spark.createDataFrame(pdf)

# Convert the Spark DataFrame back to a pandas DataFrame using Arrow
result_pdf = df.select("*").toPandas()

print("Pandas DataFrame result statistics:\n%s\n" % str(result_pdf.describe()))
```

Using the above optimizations with Arrow will produce the same results as when Arrow is not enabled.

### Additional Arrow Configurations

| Property | Default | Description |
|---|---|---|
| `spark.sql.execution.arrow.maxRecordsPerBatch` | 10,000 | Maximum number of rows for each Arrow batch. For wide DataFrames or large rows, reduce this value to avoid out-of-memory errors on the Python worker. For narrow DataFrames, increase it to reduce per-batch overhead |
| `spark.sql.execution.pythonUDF.arrow.enabled` | `true` (Spark 4.2+) | Enables Arrow optimization for regular Python UDFs. In Spark 4.2, this defaults to true |
| `spark.sql.execution.pythonUDTF.arrow.enabled` | `true` (Spark 4.2+) | Enables Arrow optimization for Python UDTFs. In Spark 4.2, this defaults to true |

### Important Considerations

**Collection to driver.** Even with Arrow, `toPandas()` results in the collection of all records in the DataFrame to the driver program. This should be done on a small subset of the data to avoid out-of-memory errors on the driver.

**Supported data types.** Not all Spark and Arrow data types are supported. An error can be raised if a column has an unsupported type. For example, `ArrayType` of `TimestampType` is not supported. `MapType` and `ArrayType` of nested `StructType` are only supported when using PyArrow 2.0.0 and above.

**Fallback behavior.** Optimizations enabled by `spark.sql.execution.arrow.pyspark.enabled` can fall back automatically to a non-Arrow implementation if an error occurs before the actual computation within Spark. This can be controlled by `spark.sql.execution.arrow.pyspark.fallback.enabled`. If an error occurs during `createDataFrame()`, Spark creates the DataFrame without Arrow.

**Pandas UDFs.** Pandas UDFs use Arrow automatically and no additional configuration is required. The `pandas_udf` decorator handles the Arrow-based data transfer internally.

**Spark 4.0+ Arrow Table conversion.** From Spark 4.0, you can create a Spark DataFrame from a PyArrow Table with `SparkSession.createDataFrame()` and convert a Spark DataFrame to a PyArrow Table with `DataFrame.toArrow()`.

### Verifying Arrow is Enabled

You can check the current value of the configuration:

```python
print(spark.conf.get("spark.sql.execution.arrow.pyspark.enabled"))
```

In the physical plan, Arrow-based operations appear as `ArrowEvalPython` or `MapInPandas` nodes. You can verify with `explain(True)`.

### Summary

To enable Arrow-based columnar data transfers in PySpark, set `spark.sql.execution.arrow.pyspark.enabled` to `true`. This enables Arrow for `toPandas()` and `createDataFrame(pandas_df)`. Ensure PyArrow is installed on all cluster nodes. In Spark 4.2+, this configuration is enabled by default. Control fallback behavior with `spark.sql.execution.arrow.pyspark.fallback.enabled`. Adjust `spark.sql.execution.arrow.maxRecordsPerBatch` to tune batch sizes for memory and performance. Pandas UDFs use Arrow automatically without additional configuration.
